# MajesticToolkit 2.1.7 — Управление финансами
> **Архив релиза.** Здесь сохранены возможности, проверки и ограничения, актуальные на момент выпуска 2.1.7. Полная последовательность изменений — в [истории версий](../CHANGELOG.md).


## Готовые пользовательские операции

В разделе **Economy & Crime → Финансы** пользователь может:

1. Создать локальный счёт/кассу и указать личного владельца или выбрать зарегистрированную семью/организацию. Начальный остаток учитывается отдельно от доходов.
2. Внести доход или расход с датой, категорией и комментарием. Списание, приводящее к отрицательному остатку, отклоняется.
3. Перевести деньги между разными счетами активного RP-профиля. Оба остатка меняются одной атомарной записью журнала. Суммарный баланс не увеличивается от переводов.
4. Установить и изменить месячный бюджет по конкретному счёту и категории, увидеть фактические расходы, оставшийся лимит и превышение. Архивировать план без удаления истории.
5. Переименовать счёт, закрыть счёт только с нулевым остатком, снова открыть его. Отменить последнюю финансовую операцию, не стирая событие из аудита.
6. Искать счета, смотреть журнал, выгружать CSV и переносить данные в Backup v19.

## Обработка данных и совместимость

- Финансовые журналы записываются в `browser.storage.local` по одному ключу `mtFinancialV217:<profileId>`. Вся финансовая операция проходит полное повторное воспроизведение событий и сохраняется единственным вызовом записи; при исключении выполняется откат.
- Лимиты денежных значений — целое количество игровых долларов от 0 до 10^12. Дробные и отрицательные значения отклоняются. Переводы не дублируют прибыль и расходы.
- Счета семьи и организации используют ID действующих реестров; удаление владельца со связанным финансовым журналом запрещено. Игровые права доступа не подтверждаются, все данные остаются локальными.
- Формат общей копии остаётся **Backup v19**, добавляется необязательное поле `financeLedger` с проверкой профилей, владельцев и полного журнала. Старые копии без `financeLedger` не удаляют нынешние финансовые данные. При ошибке многокомпонентного восстановления возвращается прежняя копия.
- **Нет автоматического переноса или синхронизации из `deal`, `cash`, Trading & Inventory**: одно хозяйственное событие не должно создавать двойных проводок. Для заполнения касс пользователь фиксирует операции самостоятельно.
- Бюджеты сигнализируют о перерасходе, но не блокируют каждое списание по категории. Отмена ограничена последним финансовым движением для однозначного воспроизведения; это не произвольное удаление истории.

## Проверки

`npm run verify`, `npm run test:browser:finance` и Chromium-регрессии Economy, Marketplace, Inventory, Families, Organizations, Crime. Модульные тесты проверяют переполнение, недостаточный остаток, перенос средств, бюджеты, историю, откат сбоя, изоляцию профилей и Backup v19.

## Установка патча

Распаковать только изменённые файлы 2.1.7 поверх **полного исходного проекта 2.1.6**. Затем выполнить `npm run verify`. Для установленного расширения собрать нужный дистрибутив по инструкции проекта.
