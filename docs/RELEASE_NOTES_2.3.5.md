# MajesticToolkit 2.3.5 — Shared Directories

## Развёртывание и обновление

1. Распакуйте архив изменённых файлов поверх полного дерева версии **2.3.4**; удалять существующую SQLite-базу и `browser.storage.local` **не требуется**.
2. Node.js 22: `npm run verify`. Для командного сервера: `npm run cloud:identity` с прямым TLS и отдельной защищённой папкой постоянных данных. Перед обновлением действующего сервера создайте согласованную резервную копию **SQLite + WAL** штатным SQLite backup API или при остановленном сервере.
3. При первом запуске SQLite расширяет `cloud_records.kind` с `family/organization` на `family/organization/product` посредством транзакционного копирования записей со всеми версиями и tombstone. Журнал `cloud_changes` и другие сущности команд сохраняются. Новый таблица `cloud_directory` разово материализуется из существующих сохранённых семей/организаций. После этого каждое изменение обновляет индекс в той же SQLite-транзакции. При сбое транзакция откатывается.
4. В разделе Team & Cloud войдите в аккаунт, выберите команду и привязанный облачный RP-профиль. По умолчанию синхронизация остаётся **выключенной**. При включении отправляются **все** семьи, организации и товары выбранного локального профиля; цены, объявления, складские операции, Tactical Toolkit, Evidence Vault и другие сведения не публикуются.
5. Для ручного импорта без автосинхронизации отметьте семьи, организации и/или товары в списке и подтвердите передачу. Повторные идентичные операции идемпотентны, несогласованные версии/ID получают HTTP 409.

## Работа со справочниками

- **Семьи, организации:** исходные записи с неизменёнными `id` и проверяемой историей событий из локальных разделов.
- **Участники:** активные и выбывшие члены семей/организаций, включая связи с источником, ранг/должность. Их нельзя произвольно изменять отдельно от истории исходной записи. Изменения выполняются в прежних семейном и организационном интерфейсах, затем синхронизируются.
- **Имущество:** активы организаций с типом, инвентарным номером, стоимостью, ответственным и состоянием. Изменяются через журнал организации.
- **Товары:** только записи Marketplace типа `product` (название, категория, вариант, единица, примечание, архивный статус). Цены, наблюдения, объявления и складские журналы являются локальными и не должны считаться синхронизированными.
- Клиенты с ролью Viewer могут читать справочники, но не импортировать или менять записи. Editor/Admin/Owner имеют право на синхронизацию, проверяемое сервером.
- При столкновении версий продукта используются прежние «Взять облачную» и «Оставить локальную»; повреждение локальных товарных ссылок блокируется. Например, серверное удаление товара с локальными объявлениями/складскими событиями остаётся конфликтом вместо удаления.

## HTTP API

`GET /v1/teams/{teamId}/cloud/profiles/{profileId}/directory?kind=family|organization|participant|asset|product&q=...&after=...&limit=30`

Возвращает `{kind,entries,nextCursor}`. Поля entry: `{id,kind,name,sourceKind,sourceId,record}`. `q` — регистронезависимый поиск по названию (включая никнейм участника) с экранированными SQLite wildcard-символами. Максимальный `limit` = 50. Для следующей страницы используйте точный серверный `nextCursor`; последний курсор отсутствует, если страниц больше нет.

Запросы `GET .../records?kind=product` и `GET/POST .../sync` от 2.3.4 поддерживают вид `product` в дополнение к `family` и `organization`, с неизменными версиями, `operationId`, RBAC и уведомлениями клиентов.

## Ограничения и приёмка

Справочники являются *командными видами существующих проверяемых записей*. Они не создают отдельную сущность человека на весь мир и не сливают одноимённых людей из разных организаций. Любое редактирование участника/актива следует выполнять в первичном журнале семьи или организации. Для удаления или архивирования связанных товаров соблюдаются ограничения Marketplace и Inventory.

Перед публичной эксплуатацией нужны HTTPS-развёртывание с резервным копированием, нагрузочные испытания индексов на больших RP-профилях, тесты нескольких реальных установленных расширений и проверка всех целевых браузеров. Локальный сервер по умолчанию слушает `127.0.0.1:8787`.
