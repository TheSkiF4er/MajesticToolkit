# MajesticToolkit 2.0.5 — Управление судебными делами
> **Архив релиза.** Здесь сохранены возможности, проверки и ограничения, актуальные на момент выпуска 2.0.5. Полная последовательность изменений — в [истории версий](../CHANGELOG.md).


**Релиз:** 2026-11-18. **База:** 2.0.4.

## Реализовано

- В `#justice` появилась вкладка **Судебные дела** и быстрые действия с реальным сохранением в `majesticGovernmentV6:`. В обзоре и поиске видны новые дела только текущего профиля; результаты открывают рабочую карточку.
- Создание и изменение дела: уникальный в профиле номер, наименование, категория, территория, суд, назначенный судья из кадрового реестра, описание. Смена суда требует согласованного назначения.
- Участники: заявитель, ответчик, представитель, свидетель, прокурор, другое лицо. Добавление, редактирование и удаление сохраняются в журнале изменений.
- Документы: связь с существующим документом Document Studio, ведомственным решением или процессуальным шаблоном. Ссылки проверяются по профилю и существованию, удаление используемой записи предотвращается. Дата привязки и название фиксируются в деле.
- Движение дела: черновик → подано → принято → рассматривается → завершено. Есть приостановка, возврат в рассмотрение, архивирование и восстановление с проверкой переходов; пользователь обязан указать основание. Дата подачи/завершения и журнал версий сохраняются в записи.
- Фильтры по суду/статусу и быстрый поиск по номеру, участникам, документам и предмету. Подсказка о совпадении по настроенным RP-правилам подсудности, без автоматического признания подсудности.

## Сохранение и совместимость

- Используется существующий Government Store и формат Backup v18: новая запись `type: 'case'` в том же ключевом пространстве, где уже находятся суды и ведомства.
- При импорте проверяются ссылки на суды и кадровые назначения, история, уникальные номера и принадлежность профилю. Записи о судебных делах не удаляются через обычную кнопку; предусмотрено архивирование. Существующие суды, решения, законы и документы не преобразуются.
- Нет сетевого API для коллективного делопроизводства. Календарь заседаний, ходатайства и протоколы являются отдельным этапом 2.0.6, хранение файлов доказательств — 2.0.8.

## Приёмочные сценарии

1. Создать действующее судебное ведомство и судебный профиль; зарегистрировать дело с уникальным номером.
2. Добавить участника, подать заявление, принять дело, начать рассмотрение, завершить и архивировать; проверить журнал причин и даты.
3. Связать существующий документ Document Studio, открыть документ из дела и запретить его удаление до отвязки.
4. Проверить, что другое RP-профиль не видит дело; что чужие суды, судьи и документы отклоняются.
5. Экспортировать и импортировать Backup v18 с судебными делами; убедиться, что существующие ведомства, суды и документы не повреждены.

**Проверки:** `npm test`, `npm run test:browser:cases`, `npm run verify`. Браузерный E2E запускается отдельно и требует Chromium с Playwright.
