# MajesticToolkit 2.3.2 — Управление командой и ролями
> **Архив релиза.** Здесь сохранены возможности, проверки и ограничения, актуальные на момент выпуска 2.3.2. Полная последовательность изменений — в [истории версий](../CHANGELOG.md).


## Рабочий сценарий

1. Запустите собственный Cloud Identity Server командой `npm run cloud:identity` (Node.js 22.13+). Для удалённого доступа используйте **прямой TLS**, `CLOUD_ALLOWED_ORIGINS` и конфигурацию из `docs/RELEASE_NOTES_2.3.1.md`.
2. Установите расширение 2.3.2, откройте рабочую область → **Team & Cloud**, подключите сервер и войдите в облачный аккаунт.
3. Создайте команду (2–80 символов). Создатель становится единственным владельцем. Команда постоянно хранится в SQLite на выбранном сервере.
4. Создайте приглашение с ролью Viewer, Editor или (для владельца) Admin. Опционально введите **точный логин существующего аккаунта** для адресного приглашения. Секретный код появляется **один раз** и больше не восстанавливается: передайте его доверенному участнику.
5. Другой участник входит в свой аккаунт и вводит код в форме «Вступить по приглашению». Он появляется в общем списке участников без перезагрузки сервера. Код погашен в транзакции и не может быть принят второй раз.
6. Owner управляет всеми участниками, меняет роли, передаёт владение и может удалить команду; Admin приглашает Editor/Viewer, меняет их роли и исключает; Editor/Viewer видят участников, но не могут управлять доступом. Участники кроме владельца могут покинуть команду.

## Инварианты безопасности

- Каждая командная операция требует живой access-сессии; `team_id` и запрошенная роль никогда не принимаются как доказательство прав клиента. Изменение прав после начала HTTP-запроса проверяется повторно непосредственно в транзакции записи.
- Сессии и членство сохраняются в SQLite. При отзыве устройства/выходе доступ к командным API прекращается немедленно, в том числе при прямых HTTP-запросах.
- Только участники могут узнать детали команды; посторонние аккаунты получают HTTP 404. Проверяются изменяемые поля и ID, действуют ограничения: до 20 созданных команд на аккаунт, 250 участников и 100 активных приглашений на команду.
- Одноразовый код приглашения создаётся `crypto.randomBytes(32)`, в БД хранится только SHA-256; код истекает через 7 дней или при отзыве. Адресное приглашение принимает только назначенный аккаунт. Реестр выдаёт метаданные, не секрет.
- Роль Owner назначается только транзакционной передачей владения. Единственный владелец не может выйти или понизить себя через смену роли. Admin не может назначать Admin/Owner или изменять Admin/Owner.
- Журнал событий команды записывает создание, приглашения, изменения ролей, удаления, выход и передачу владения. Удаление команды каскадно удаляет её участников, приглашения и журнал.
- Доступ к серверу по HTTP разрешён расширением **только** для `127.0.0.1`. Публичное развертывание требует реальный TLS, защищённые права на файлы, бэкапы SQLite/WAL, ограничения сети и мониторинг. Встроенная SQLite-реализация рассчитана на один процесс, не распределённый кластер.

## Проверки

```sh
node --test tests/cloud-teams-232.test.mjs tests/cloud-identity-231.test.mjs
npm run verify
npm run test:browser:cloud
```

Новые интеграционные тесты запускают реальный HTTP-сервер с временной SQLite, проверяют межаккаунтную изоляцию, вступление, отказ во всех запрещённых RBAC-действиях, срок действия и отзыв приглашения, сохранение после перезапуска, передачу владения, окончание сессии и background RPC. Chromium UI smoke использует изолированный адаптер браузера; требуется отдельная ручная проверка установленного расширения с настоящим публичным HTTPS-сервером.

## Границы релиза

Командное членство и полномочия работают, но **общие рабочие записи, синхронизация RP-профилей, файлы и совместные тактические карты** ещё не реализованы: это версии 2.3.3–2.3.8. Полномочия распространяются только на Cloud Team API, **не** на локальные данные другого участника и не на права в игре или сторонних сервисах. Не подразумевается уже развёрнутый общедоступный сервер.
