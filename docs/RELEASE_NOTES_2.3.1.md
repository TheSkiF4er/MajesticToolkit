# MajesticToolkit 2.3.1 — Cloud Identity & Authentication

## Реализовано

В рабочем пространстве откройте **Cloud Identity** (`ui/workspace.html#cloud`). Укажите URL своего сервера; расширение запросит доступ **только к выбранному origin**. Подключение проверяет `/v1/health`. Регистрация создаёт настоящий серверный аккаунт по логину (3–32 латинских символа) и паролю (12–128 символов), сразу открывает сессию. Вход на другом устройстве создаёт отдельную сессию. Кнопки «Отозвать», «Выйти» и «Завершить все сессии» делают серверные запросы и немедленно закрывают соответствующие сессии.

Access-токен действует 15 минут, refresh — до 30 дней с момента выдачи. При восстановлении фонового процесса расширение использует refresh для продолжения. При обновлении refresh-токен меняется и прежний не может использоваться повторно (replay приводит к отзыву сессии). В SQLite хранятся только SHA-256 токенов и scrypt-хеши паролей (N=32768, r=8, p=1), отдельная соль для каждого аккаунта. Сессии имеют стабильный ID устройства, дату создания, последнее использование, срок жизни. Поиск и отзыв чужих сессий запрещены. Неверные пароли ограничиваются персистентной блокировкой по логину и адресу источника.

Облачный аккаунт не является аккаунтом Majestic RP, Google или SkiF4er ID. В 2.3.1 не синхронизируются локальные рабочие данные, нет команд, RBAC, email verification, сброса пароля или 2FA. Эти функции не подразумеваются и не объявляются реализованными.

## Быстрый локальный запуск (Node.js 22.13+)

```sh
npm run cloud:identity
```

Сервер запустится **только на `127.0.0.1:8787`** и создаст `cloud-identity/data/identity.sqlite` (WAL). В разделе Cloud Identity укажите `http://127.0.0.1:8787`. HTTP для других хостов блокируется расширением. Локальный тест предназначен исключительно для одного компьютера, не для доступа через публичный интернет.

## Публичное развёртывание

Сервер требует **прямое TLS** (нет доверия к непроверенным `X-Forwarded-*`). Установите реальный сертификат и ключ сервера, DNS, безопасные права на файлы, резервное копирование SQLite вместе с WAL, отдельный учётный пользователь и ограничение доступа к порту средствами сети. Пример:

```sh
CLOUD_HOST=0.0.0.0 CLOUD_PORT=8787 \
CLOUD_DB_PATH=/var/lib/majestictoolkit/identity.sqlite \
CLOUD_TLS_CERT_FILE=/etc/ssl/majestictoolkit/fullchain.pem \
CLOUD_TLS_KEY_FILE=/etc/ssl/majestictoolkit/privkey.pem \
CLOUD_ALLOWED_ORIGINS='chrome-extension://YOUR_EXTENSION_ID,moz-extension://YOUR_EXTENSION_UUID' \
node cloud-identity/server.mjs
```

Клиент подключается по `https://identity.example.org:8787` (замените на фактический DNS/порт). В `CLOUD_ALLOWED_ORIGINS` следует указать **точные** доверенные Origins установленных расширений. Для Firefox временные UUID отличаются между установками. Если расширение браузера предоставляет host permission для выбранного сервера, CORS может не потребоваться, но сервер всё равно блокирует посторонние Origin-заголовки.

Не используйте публичный HTTP. Не размещайте TLS-ключ, базу SQLite или данные аккаунтов внутри расширения либо репозитория. Рекомендуется дисковое шифрование сервера, бэкапы, мониторинг ошибок и внешний security review перед обслуживанием реальных пользователей. Встроенный `node:sqlite` Node.js 22 пока отмечен Node как экспериментальный API; проверяйте выбранную LTS-сборку перед обновлением. Для нескольких реплик требуется внешний координатор и управляемое хранилище: конфигурация 2.3.1 рассчитана на **один процесс Identity Server**, а не кластер.

## API для проверки

- `POST /v1/auth/register`, `POST /v1/auth/login`: имя, пароль, название устройства → сессия и токены;
- `POST /v1/auth/refresh`: обновление и ротация;
- `GET /v1/auth/me`, `GET /v1/auth/sessions`: проверка и список;
- `DELETE /v1/auth/sessions/:id`, `POST /v1/auth/logout`, `POST /v1/auth/logout-all`: отзыв;
- `GET /v1/health`: проверка готовности процесса.

Облачный refresh-токен сохраняется в изолированном хранилище расширения (`mtCloudIdentitySessionV231`); access-токен остаётся только в памяти background. Токены **не возвращаются UI**. Локальное хранилище браузера само по себе не зашифровано — используйте защищённый профиль ОС и не копируйте его в постороннюю среду. Если устройство потеряно, завершите его сессию с другого доверенного устройства. При отключённой сети обычный logout не выдаётся за успешный серверный отзыв: можно отдельно удалить локальные токены с предупреждением, что удалённая сессия ещё активна. Не включайте данные аккаунта или токены в экспорт Backup v21.

## Проверки

`npm run verify` — Node.js unit + integration, синтаксис, четыре браузерные сборки и SHA-256 пакетов. Дополнительный тест `node --test tests/cloud-identity-231.test.mjs` проверяет создание аккаунтов, вход с двух устройств, отзыв, refresh/replay, сохранение SQLite после перезапуска, блокировки и клиентский background. Ручная проверка HTTPS в реальном браузере и установленных расширениях остаётся отдельным шагом перед публичным запуском.
