# Модель безопасности MajesticToolkit

**Для версии 2.4.0** · [Политика конфиденциальности](PRIVACY.md) · [Требования к публичной эксплуатации](RELEASE_NOTES_2.4.0.md)

> Это описание реализованных границ безопасности и оставшихся ограничений. Автоматические тесты не заменяют независимую проверку приложения, сервера и браузерных интеграций.

## Модель доверия

Страницы RP-форумов, видеосайтов и внешних источников считаются **недоверенными**. Контентные скрипты получают только необходимые им данные через ограниченные сообщения фонового процесса. Например, `RP_NEXUS_FORUM_DATA` передаёт шаблоны текущего профиля и краткие сведения о профиле, а `RP_NEXUS_VIDEO_CASES` — идентификаторы и заголовки жалоб. Фоновый процесс проверяет источник запроса до выполнения действия.

Расширение не должно обходить права форума, открывать закрытые данные сайта или автоматически публиковать сообщения и санкции. Внешние тексты, ссылки, материалы и результаты ИИ необходимо проверять перед использованием.

## Разрешения браузера

Доступ к RP-форумам, видеохостингам, Google API и локальному шлюзу запрашивается как **необязательный**. В действующих манифестах 2.4.0 присутствует также `https://*/*` среди необязательных адресов: при выдаче разрешения пользователь должен понимать область доступа. При развитии проекта рекомендуется сужать её до необходимого набора доменов или точных адресов самостоятельно размещённого Cloud-сервера.

Не добавляйте постоянный доступ `<all_urls>`, небезопасную политику CSP или загрузку исполняемого JavaScript с удалённых сайтов. Код Manifest V3 должен входить в собранный пакет.

## Локальные данные

Хранилище браузера **не шифруется на уровне приложения**. Защитите профиль ОС и устройство; резервные копии храните отдельно. OAuth-токены не входят в JSON-резервные копии и локальные снимки отката. SHA-256 помогает обнаружить повреждение, но **не является подписью** и не защищает от атакующего, способного изменить данные и саму контрольную сумму.

Перед удалением расширения или заменой его идентификатора экспортируйте резервную копию.

## Облачные аккаунты и команды

Самостоятельно размещённый Cloud Identity Server хранит учётные записи, роли, сессии и командные данные в SQLite. Для внешнего доступа требуется HTTPS, точный список `CLOUD_ALLOWED_ORIGINS` и отдельная защита секретов. Командные операции проверяют права на стороне сервера, а синхронизация выбранных RP-данных включается по действию пользователя.

Исторические версии облачных файлов со статусом `private` должны оставаться доступными только владельцу — в том числе после публикации последующих общих редакций. Это правило усилено в версии 2.4.0 и проверяется регрессионными тестами.

**Граница доверия:** данные на облачном сервере не шифруются сквозным образом для администратора сервера. Администратор хостинга и лица с доступом к серверной базе и копиям могут потенциально прочитать содержащиеся в них материалы. Размещайте сервер только на доверенной инфраструктуре, защищайте файлы SQLite, снимки и токены.

## Резервное копирование и восстановление

Для серверных снимков действуют проверки SQLite, связности записей и SHA-256 содержимого файлов и карт. Не размещайте резервные копии в общедоступном каталоге, шифруйте их средствами инфраструктуры и **проверяйте реальное восстановление**. Возврат старого снимка может восстановить ранее отозванные сессии; после инцидента следует оценить их принудительный отзыв.

## Локальный шлюз ИИ

Ключ OpenAI должен оставаться в окружении локального процесса Node.js. В расширение вводится отдельный токен шлюза. Запрос выполняется только после предпросмотра и явного согласия пользователя. Шлюз привязан к `127.0.0.1` и **не рассчитан на публикацию в интернете**. Результаты ИИ не являются проверенными решениями или основаниями для автоматических санкций.

[Настройка шлюза](../ai-gateway/README.md)

## Сообщения об уязвимостях

Не прикладывайте к публичным GitHub Issues токены, пароли, документы с персональными сведениями, содержимое жалоб или резервные копии. Для конфиденциального сообщения об уязвимости используйте GitHub Security Advisories репозитория, если функция доступна.

## Области, требующие отдельной приёмки

Не следует заявлять о выполнении независимого пентеста, проверки магазинами, реальной авторизации Google, полного испытания установленного расширения на действующих RP-форумах или продолжительного промышленного нагрузочного тестирования без соответствующих результатов. До публичного развёртывания эти проверки должны выполняться отдельно.
