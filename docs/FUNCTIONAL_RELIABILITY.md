# MajesticToolkit 1.5.2 — Functional Reliability Hotfix

## Исправленные сценарии

1. В рабочем пространстве откройте **Форум → Пользовательская навигация XenForo**, укажите название, HTTPS-ссылку и профиль и нажмите **Сохранить ссылку**. Форма не перезагружает страницу; ссылка появляется в списке и после открытия форума — в его навигации.
2. Выберите шаблон и нажмите **Вставить в форум**. Теперь выбирается соответствующая ранее открытая вкладка форума, даже если рабочее пространство находится на переднем плане. Нельзя отправить шаблон для одного проекта во вкладку другого.
3. Откройте форум и предоставьте для него доступ через **Сайты и доступ**. Уже открытые вкладки получают панель без обязательной перезагрузки, если браузер разрешает исполнение; при ошибках внедрения можно обновить страницу.
4. Если рабочая панель не получает ответ фонового процесса, она больше не сохраняет старые данные и отображает понятное сообщение о причине.

## Контроль качества

`npm run verify` проверяет тесты, собирает четыре MV3-пакета и проверяет их контрольные суммы. Отдельно запускайте `npm run test:browser` для тестовых DOM-фикстур, требующих установленного Playwright.

На живых форумах и на уже опубликованном расширении под AMO требуются отдельные приёмочные испытания. Обновление не меняет ID расширения и не затрагивает уже сохранённые локальные данные.


## Firefox Android: доступ к форумам (исправление 1.5.2)

На Firefox Android вызов `browser.permissions.request` должен выполняться из непосредственного обработчика нажатия. Предыдущее выполнение `await browser.permissions.contains()` перед запросом прерывало пользовательскую активацию и вызывало `permissions.request may only be called from a user input handler`. В 1.5.2 кнопки Majestic RP и Russia Online используют предварительно загруженное состояние разрешений. `changeHostPermission()` вызывается синхронно, до любого `await`, затем состояние перечитывается и отображается в UI. Аналогично исправлено управление доступом видеооверлея.

Новый тест `tests/permission-gesture-152.test.mjs` моделирует потерю активации после асинхронной проверки, проверяет успешный вызов до первого `await`, отмену разрешения, изоляцию доменов и отсутствие запроса неизвестных адресов. Browser E2E включает клик по разрешению в автономной странице с имитацией API и не является тестом разрешений настоящего Firefox Android.

## Устойчивость и интеграции

- Необязательные разделы загружаются через `Promise.allSettled`, чтобы недоступность одного хранилища не блокировала остальные. Появляется предупреждение и кнопка «Повторить загрузку»; неисправность основного состояния профилей по-прежнему открывает механизм восстановления.
- Перед Google OAuth-запросом проверяется ранее сохранённый Client ID без дополнительного `await` между нажатием и `permissions.request`.
- Имя Google Drive backup теперь содержит текущую версию приложения.

### Ручная приёмка, которую необходимо выполнить на устройстве

1. В Firefox Android откройте «Сайты и доступ», выдайте права обоим форумам; убедитесь, что появляется системное подтверждение, статус становится «Доступ предоставлен», а панель появляется после открытия страницы форума.
2. Отзовите разрешения и повторно выдайте их, проверьте обновление открытых вкладок и сохранность локальных шаблонов.
3. Временно отключите сетевые и Google интеграции и убедитесь, что локальные разделы открываются, а повторная загрузка восстанавливает работоспособность после устранения причины.
4. Проверьте Google OAuth с собственным Client ID и сохранение backup в Drive; проверьте имя файла и отказ без ID.

Эти проверки нельзя считать выполненными лишь по результатам CI или тестов с имитацией WebExtension API.
