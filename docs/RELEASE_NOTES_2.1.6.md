# MajesticToolkit 2.1.6 — Crime & Territory Operations

## Рабочие функции

- Девятая вкладка `#economy` → «Территории и капты»: регистрация, редактирование и архивирование территорий с историей смены владельцев.
- Проведение каптов, организационных противостояний и иных RP-событий с указанием даты, участников, сторон, результатов и комментариев. Запланированные события можно изменять и отменять; завершённые записи неизменяемы и сохраняют журнал.
- Владение территорией рассчитывается только по завершённым каптам. При победе нападающей стороны владелец меняется; победа защитника или ничья не меняют владельца. Проверяются последовательность захватов и допустимость стороны защитника на дату события.
- Команды ссылаются на реальные записи семей и организаций внутри того же RP-профиля. Исторические связи сохраняются при переименовании, удаление используемых семей и организаций запрещено.
- Протокол события с участниками, K/D и уроном. По завершённым событиям строятся рейтинги семей/организаций и отдельных игроков. Старые `match` остаются отдельно, не перезаписываются и не суммируются повторно.
- Поиск, CSV-экспорт, проверка ввода, защита от HTML/CSV-инъекций, журнал правок и профильная изоляция.

## Хранилище и резервное копирование

- Новые локальные ключи `mtTerritoriesV216:` и `mtCrimeEventsV216:`. Все записи проходят полный replay журнала при чтении; при повреждении, дублировании ID, недействительном владельце или принадлежности чужому профилю операция отклоняется.
- Backup v19 сохраняет дополнительные поля `territories` и `crimeEvents`, включая журналы и ссылки. Новая структура проверяется при экспорте и до начала импорта. Старый Backup v19 без этих полей не удаляет новые локальные данные.
- При удалении RP-профиля удаляются его территории и события, а при ошибке выполняется откат с сохранением исходных записей.

## Ограничения

- Это локальный журнал RP-событий. Автоматическое считывание каптов и территории с игрового сервера, фоновая синхронизация и подтверждение права на владение не реализованы.
- Статистика формируется только из введённых пользователем завершённых событий. Утверждённый итог не редактируется — ошибочное событие необходимо исправлять через восстановление резервной копии, а не скрыто переписывать результат.
- Backup v20 по roadmap относится к последующим релизам; здесь сохраняется совместимый формат v19.

## Проверка

```
npm run verify
npm run test:browser:crime
```

Тесты охватывают состояния территорий и каптов, состав, расчёт статистики, контроль владельца, повреждённые записи, восстановление, профильные границы и браузерные пользовательские действия. Для реальной production-публикации остаются проверки установленного расширения в целевых браузерах и на целевом RP-проекте.
