# MajesticToolkit 2.1.8 — Расширенная экономическая аналитика
> **Архив релиза.** Здесь сохранены возможности, проверки и ограничения, актуальные на момент выпуска 2.1.8. Полная последовательность изменений — в [истории версий](../CHANGELOG.md).


## Пользовательский сценарий

1. Откройте `#economy`, выберите вкладку «Аналитика».
2. Выберите даты, тип владельца кассы и конкретный товар (необязательно). Настройки фильтров сохраняются локально отдельно для каждого RP-профиля.
3. Изучите денежные потоки и сравнение с предшествующим периодом той же длины. Остатки счетов показывают **текущий** баланс, не исторический.
4. Посмотрите результаты складских продаж и списаний по товарам. Текущий запас отображается отдельно от прибыли за период.
5. Посмотрите медианные цены по каждому товару и динамику дневных медиан. При наличии состоявшихся сделок медиана строится по ним, иначе — по наблюдениям с явной отметкой.
6. Сохраните CSV, содержащий показатели, дневные потоки, категории, счета, товары и даты цен.

## Источники и ограничения

- Счета: `finance-store`, отменённые движения исключаются, внутренние переводы не превращаются в доход/расход.
- Старые `deal/cash`: отдельная сводка, не объединённая с балансами и складом.
- Склад: `inventory-store`, прибыль учитывает комиссии, себестоимость партий и списания.
- Рынок: `marketplace-store`, **только локальные** пользовательские наблюдения. Историческую активность объявлений задним числом по текущему статусу достоверно восстановить нельзя.
- Владельцы счётов связываются по стабильным ID семьи/организации. У складских владельцев хранятся текстовые имена, поэтому фильтр владельца кассы не применяется к складу.
- Записи пользователей не изменяются при аналитических запросах.
- Backup v19 сохраняется без миграций, параметры интерфейса можно восстановить в том же браузере.

## Проверки

Запустите `npm run verify`, `npm run test:browser:analytics`. Тесты покрывают профильную изоляцию, расчёты, границы дат, независимость учёта и экспорт.
