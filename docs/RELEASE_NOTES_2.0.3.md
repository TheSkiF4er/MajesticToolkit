# MajesticToolkit 2.0.3 — Государственные ведомства
> **Архив релиза.** Здесь сохранены возможности, проверки и ограничения, актуальные на момент выпуска 2.0.3. Полная последовательность изменений — в [истории версий](../CHANGELOG.md).


## Готовые пользовательские операции

Откройте **Workspace → Government & Justice → Ведомства** либо **Ведомства** в основном меню. В подразделе **Ведомства** создайте запись ведомства с именем, сокращением, юрисдикцией и ответственным. Перейдите к **Подразделениям**, выберите ведомство и добавьте корневое подразделение и дочерние структуры. В подразделе **Компетенции** создайте описания полномочий с уникальным кодом и необязательным правовым основанием. В **Должностях** создайте штатные позиции, привяжите к подразделению и отметьте их компетенции. В **Назначениях** укажите RP-имя сотрудника, должность, начало и при необходимости окончание исполнения. Редактирование назначения сохраняет предыдущие значения и указанную причину в локальной истории.

Записи можно редактировать, архивировать, восстанавливать и удалять при отсутствии зависимостей. При попытке удалить подразделение, компетенцию или должность, на которую ссылаются другие записи, будет выведена ошибка и удаление не произойдёт. Создавать новые назначения на архивные должности нельзя. В штатном реестре есть поиск, фильтр ведомств и скачивание CSV. Суды в Workspace могут открыть свою штатную структуру.

## Совместимость и пределы

Все новые записи используют тот же локальный Government Store (`majesticGovernmentV6:`), что и старые ведомства, решения и шаблоны. Все записи проходят текущий механизм проверки и сохранения Backup v18, без изменения его schemaVersion. Для импорта из более старых версий ничего дополнительно делать не нужно. Данные из разных профилей не смешиваются. Должности и компетенции фиксируют **описание RP-полномочий**, но **не** предоставляют реальные игровые полномочия и не заменяют серверную систему разграничения доступа. Нет общей сетевой синхронизации и судебного реестра дел в этом релизе.

## Проверка

`npm test`, `npm run build`, `node scripts/verify.mjs`, Chromium browser E2E (`python3 tests/browser-e2e.py`). E2E проходят на локальных тестовых данных, не на подключённых игровых серверах. Для установки патча 2.0.3 распакуйте изменённые файлы поверх **полного** проекта 2.0.2 с сохранением каталогов, затем выполните `npm test` и `npm run build`.
