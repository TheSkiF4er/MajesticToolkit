# MajesticToolkit 2.2.8 — Tactical Analytics & Replay

## Как пользоваться

1. В `Economy & Crime → Территории и капты` фиксируйте настоящие RP-события и их результаты; в `Tactical Toolkit → Аирдропы` регистрируйте точки, получение наград и завершение событий. Отдельно загружать данные в аналитику не требуется.
2. В `Tactical Toolkit → Аналитика и replay` выберите даты и категорию. Сводка, распределение по дням, рейтинг семей и организаций, участники и хронология рассчитываются из проверенных сохранённых журналов выбранного RP-профиля.
3. Передвигайте ползунок истории, нажимайте «Назад», «Вперёд» или «Воспроизвести». Если в `Карта` имеется подложка с привязанными территориями, Canvas показывает владельцев с учётом завершённых каптов на данном шаге. Зарегистрированные точки аирдропов показываются только на совпадающей подложке.
4. Выберите сохранённый сценарий в блоке сравнения: маршрут симуляции будет показан пунктиром поверх карты при совпадении SHA-256, а модельные расстояния, минуты и пересечения — отдельно от фактических результатов. Сохранённые симуляции и записи каптов не изменяются.
5. Экспортируйте отфильтрованный временной ряд в CSV с защитой от формул либо JSON. Настройки дат и категории сохраняются отдельно в каждом RP-профиле.

## Гарантии и ограничения

- `tactical-analytics-core.mjs` использует `validateCrime`, `validateAirdrops` и `cleanTacticalSimulation`. Ошибка или повреждение журнала блокируют вычисление вместо пропуска записи. Нет второго журнала владения или автоматического изменения каптов.
- История владельцев вычисляется по исходному владельцу и зарегистрированным завершённым каптам. При фильтрации по аирдропам или другим событиям изменение владельца между шагами всё равно учитывается; история до начала выбранного периода сохраняется в исходном состоянии воспроизведения.
- Капты имеют **точность до дня**, потому что в Crime Store записана дата события, но не точное время матча. Для упорядочения в смешанной временной шкале используется условное 12:00 UTC. Временные метки действий аирдропа берутся из его журнала. Replay не является видеозаписью и не дорисовывает незарегистрированные перемещения игроков.
- Подсчёт показателей групп, K/D и урона выполняется только по завершённым RP-противостояниям за выбранный период. Снимок аналитики не изменяет фактические данные. Сравнение с моделью **не** является оценкой точности модели исходов: реальные траектории не записываются.
- Для плавного воспроизведения введён явный лимит 1500 событий после фильтрации. Если журнал длиннее, интерфейс просит сузить период; незаметного усечения данных нет.
- Данные карты, аирдропов, планов и симуляций пока не включены в Backup v20. Экспорт CSV/JSON аналитики предназначен для отчётов; сквозной перенос ресурсов карты запланирован для Backup v21 в 2.2.9.

## Проверки

`npm run verify` — Node.js, сборки и проверка четырёх платформ. `npm run test:browser:tactical-analytics` — пользовательский Chromium E2E с настоящим Canvas, загрузкой подложки и изолированным тестовым IndexedDB, созданием капта и аирдропа, replay, сравнением симуляции, экспортом и проверкой изоляции RP-профилей.

Установленное расширение на игровом сервере Majestic RP не тестировалось, игровой API не подключён.
