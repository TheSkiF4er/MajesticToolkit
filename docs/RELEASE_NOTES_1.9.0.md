# MajesticToolkit 1.9.0 — Доказательства и знания
> **Архив релиза.** Здесь сохранены возможности, проверки и ограничения, актуальные на момент выпуска 1.9.0. Полная последовательность изменений — в [истории версий](../CHANGELOG.md).


## Результат

Реальный интегрированный Evidence & Knowledge Workspace на существующих локальных модулях Evidence Vault 2.0, Evidence Timeline, Knowledge Center 2.0, графа источников и Case Dossier & Export. Включены шесть рабочих вкладок, поиск досье, живые профильные показатели и прямые переходы к делам и источникам.

## Рабочий сценарий

1. Откройте `Workspace → Evidence & Knowledge` или команду в панели XenForo.
2. На вкладке **Материалы** загрузите файл или добавьте HTTPS-ссылку. Данные IndexedDB сохраняются локально и проверяются SHA-256.
3. На вкладке **Таймлайны и дела** выберите жалобу и создайте события с видеофрагментами и участниками.
4. На вкладке **Центр знаний** вручную импортируйте статью, создайте коллекцию, сравните редакции и сохраните цитату; граф находится на отдельной вкладке.
5. На вкладке **Граф и цитаты** создайте типизированные связи с доказательствами, правилами, событиями и решениями.
6. На вкладке **Досье и экспорт** найдите дело и откройте действующий диалог для JSON, HTML, TXT, BBCode или ZIP с манифестом SHA-256 и доступными файлами.

## Хранение и обратная совместимость

Существующие жалобы, вложения, редакции, ссылки, санкции и цитаты не мигрируют в новую несовместимую базу: используются прежние источники данных. Дополнительно в профиль сохраняется `evidenceKnowledge = {tab, days, caseId}` с проверкой допустимых значений. Параметры входят в прежний Backup v17. Старые резервные копии v1–v16 поддерживаются. JSON-экспорт переносит только метаданные файлов IndexedDB, для переноса бинарных вложений нужен Portable ZIP v17.

## Защита и ограничения

- Недоступность IndexedDB сообщается отдельно; не считать отсутствие доступа доказательством отсутствия файлов.
- Данные всегда выбираются для текущего профиля, проекта и сервера. ID дела из URL проверяется до открытия.
- Внешние видео и источники не скачиваются автоматически. Для открытия соответствующих сайтов используются существующие разрешения.
- SHA-256 удостоверяет целостность полученных локальных байтов, не подлинность источников или видео.
- Отправка решений на форум, модерация и выдача игровых санкций не автоматизированы.
- Chromium E2E выполняются на автономных фикстурах с имитацией API браузерных расширений. Реальные авторизованные форумы, Firefox Android и Safari на физических устройствах требуют отдельной приёмки.

## Локальная проверка

```bash
npm run verify
npm run test:browser
```

Новые профильно-изолированные настройки, агрегация действующих хранилищ, резервное копирование и оболочка проверяются дополнительно модульными и Chromium UI-тестами.
