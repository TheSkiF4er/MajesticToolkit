# Подготовка и публикация выпуска MajesticToolkit

**Актуальная версия: 2.4.0** · [Готовый выпуск](https://github.com/TheSkiF4er/MajesticToolkit/releases/tag/v2.4.0) · [Заметки о выпуске](RELEASE_NOTES_2.4.0.md)

> Это руководство описывает **воспроизводимость сборки и проверки перед публикацией**. Успех автоматических тестов сам по себе не означает успешную модерацию в магазинах, подписание Safari или приёмку на реальном RP-форуме.

## 1. Проверить исходники

Требуется **Node.js 22.x**. У проекта нет внешних npm-зависимостей для сборки.

```bash
node --version
npm run verify
```

`npm run verify` запускает Node.js-тесты, формирует четыре браузерных пакета в `dist/` и `release/`, проверяет разрешения и синтаксис, создаёт `release/release-manifest.json` и `release/SHA256SUMS` и сверяет содержимое ZIP с каталогами сборки.

| Файл | Назначение |
| :--- | :--- |
| `MajesticToolkit-2.4.0-chromium.zip` | Браузеры на Chromium. |
| `MajesticToolkit-2.4.0-firefox.zip` | Firefox для компьютера. |
| `MajesticToolkit-2.4.0-firefox-android.zip` | Отдельный вариант Firefox Android. |
| `MajesticToolkit-2.4.0-safari.zip` | Ресурсы для дальнейшей упаковки Safari. |
| `SHA256SUMS` | Контрольные суммы файлов выпуска. |
| `release-manifest.json` | Список пакетов, размеры и SHA-256. |

Для Linux проверьте суммы из каталога с **всеми четырьмя** архивами:

```bash
cd release
sha256sum -c SHA256SUMS
```

Если загружен только один пакет, сверяйте только его строку. На Windows для отдельного файла используйте `Get-FileHash -Algorithm SHA256`.

## 2. Выполнить приёмку

Автоматизация покрывает не все сценарии. Перед распространением проверьте:

1. **Chromium:** реальную установку в Chrome/Edge, перезапуск фонового процесса, всплывающую и боковую панели, рабочее пространство, сохранение данных.
2. **Firefox:** подписанный пакет, доступ к форуму, редакторы XenForo, шаблоны, смену профилей и разрешения.
3. **RP-процесс:** профиль → форум → жалоба → доказательства → решение → документ → экспорт, резервная копия → импорт → проверка отката.
4. **Firefox Android:** установку и работу разрешений на физическом устройстве, адаптацию узких экранов.
5. **Safari:** создание приложения средствами Apple, подпись и проверку на подходящих устройствах.
6. **Необязательные интеграции:** реальный OAuth Google, работа внешних API при разрешённом подключении, отказы сети и восстановление.
7. **Защиту границ:** отсутствие доступа между чужими профилями, корректный отказ без разрешения форума, отсутствие автоматической отправки сообщений и санкций.
8. **Облачный режим:** роли команды, отзыв доступа, защищённые вложения, резервное копирование и проверенное восстановление.

В CI задача `browser-e2e` запускает браузеры на **локальных фикстурах XenForo**. Она не заменяет испытания с реальной авторизацией на форумах. Подробности: [готовность к выпуску](PRODUCTION_READINESS.md).

## 3. Подготовить публикацию

- **GitHub Releases:** публикуйте архивы, `SHA256SUMS`, манифест и русскоязычные заметки из `docs/RELEASE_NOTES_<версия>.md`. Привязывайте выпуск к проверенному коммиту.
- **Mozilla Add-ons:** сформируйте Firefox-архив через `npm run build-for-amo`; проверьте его и предоставьте соответствующие исходники, политику приватности и описание необязательных разрешений. [Инструкция подачи](AMO_SUBMISSION.md).
- **Chrome Web Store и Microsoft Edge Add-ons:** используйте Chromium-архив и отдельные карточки магазина, сведения о конфиденциальности и реальные скриншоты.
- **Safari:** предоставленный ZIP содержит только ресурсы расширения. Соберите нативный контейнер, подпишите и распространите его средствами Apple.

**Особенность опубликованного 2.4.0:** workflow `.github/workflows/publish-release-2.4.0.yml` привязан к этой версии и **не перезаписывает уже опубликованные материалы**. Изменение только документации в исходной ветке не обновляет автоматически заметки или ZIP существующего выпуска. Для следующей версии обновляйте `package.json`, все браузерные манифесты, заметки, имена артефактов и конфигурацию публикации, затем запускайте проверку на новом коммите.

## 4. Обновить проект без потери данных

Перед обновлением сохраните резервную копию локальных записей. Для серверного режима отдельно создайте проверенный снимок SQLite и храните его вне каталога расширения. Не смешивайте архив изменённых файлов с деревом другой версии. После наложения изменений выполните `npm run verify` и повторите критические пользовательские сценарии.
