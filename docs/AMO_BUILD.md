# Mozilla AMO: воспроизводимая сборка (MajesticToolkit 1.5.5)

Этот документ является инструкцией для рецензента. **Исходный архив содержит авторский код до сборки:** файлы из `src/`, манифесты из `manifests/`, скрипты `scripts/`, тесты и документацию. В исходный пакет **не нужно** помещать машинно сгенерированные `dist/` или `release/`. Бандлеры и минификаторы не используются. Все исходные файлы читаемы и копируются в сборку без транспиляции. Mozilla получает их именно в первоначальном виде.

## 1. Требования к ОС и инструментам

- **Проверенная среда:** Linux x86_64, Node.js **22.16.0**, npm **10.9.2**.
- **Поддерживаемая среда сборки:** современная Windows 10/11 (PowerShell), macOS 13+ или Linux (например, Ubuntu 24.04), Node.js 22.x; npm, поставляемый с Node 22.x. Браузер для сборки не нужен.
- **Дополнительные зависимости:** отсутствуют. Требуются только встроенные модули Node.js (`fs`, `path`, `zlib`, `crypto`, `child_process`), Git **не обязателен**.
- **Подключение к интернету:** не требуется для сборки или тестов. Установка Node.js может требовать интернета.
- **Дополнительные пакеты npm:** не требуются; **не запускайте `npm install`**. Папка `node_modules` для воспроизведения не нужна.

### Установка Node.js 22

1. Откройте официальный сайт [Node.js](https://nodejs.org/en/download) и выберите выпуск **22.16.0** для своей ОС (можно использовать официальный архив релиза `https://nodejs.org/dist/v22.16.0/`).
2. На Windows запустите MSI-установщик и разрешите добавление Node.js в `PATH`; откройте новый PowerShell.
3. На macOS запустите `.pkg` либо установите официальный tarball и добавьте `bin/` в `PATH`.
4. На Linux распакуйте официальный `node-v22.16.0-linux-x64.tar.xz` и добавьте каталог `bin/` в `PATH`. На ARM64 используйте соответствующую сборку Node 22.
5. Убедитесь, что выполняются `node --version` → `v22.16.0` и `npm --version` → `10.9.2`.

## 2. Точное воспроизведение отправляемого ZIP

1. **Полностью распакуйте исходный архив** в пустую папку. В корне должны находиться `package.json`, `README.md`, `src/`, `manifests/`, `scripts/`, `tests/`, `LICENSE`.
2. Откройте терминал или PowerShell в корне распакованной папки.
3. Выполните:

   ```sh
   npm run build-for-amo
   ```

4. Команда автоматически: удалит и создаст `dist/`, скопирует исходные ресурсы, запишет платформенные `manifest.json`, проверит синтаксис и разрешения, создаст воспроизводимые ZIP-файлы для всех четырёх платформ, проверит SHA-256 и побайтовое содержимое каждого ZIP.
5. Результат для Firefox Desktop: **`release/MajesticToolkit-1.5.5-firefox.zip`**. Для Android: `release/MajesticToolkit-1.5.5-firefox-android.zip`.
6. Полный прогон регрессионных тестов выполняется отдельно командой:

   ```sh
   npm run verify
   ```

   Она повторяет сборку и проверку после тестирования. Для проверки SHA-256 используйте `release/SHA256SUMS` или `release/release-manifest.json`.

## 3. Фактические операции сборки

- `scripts/build.mjs` **не изменяет код JavaScript**. Все файлы в `src/lib`, `src/ui`, `src/content`, `src/background`, `src/assets`, `src/_locales` копируются без транспиляции, объединения и минификации.
- Каждая платформа получает свой `manifest.json`, сформированный копированием декларации соответствующего файла из `manifests/`. Для Android применяется удаление несовместимого `sidebar_action`; для Safari удаляются десктопные параметры.
- В отличие от ранних сборок, фоновый код Firefox и Chromium использует **исходные статические ESM-импорты**, без динамической генерации JS-кода сборщиком.
- `scripts/package.mjs` формирует ZIP без сетевых запросов, с фиксированными временем и порядком записей.
- Скрипты `scripts/verify.mjs` и `scripts/check-release.mjs` проверяют состав сборок, допустимые разрешения, контрольные суммы и полное совпадение ZIP-файлов с `dist/`.

**Предупреждение:** если пакет уже отправлен в AMO, исходники должны соответствовать *именно той версии ZIP*, которая приложена к заявке. После изменения кода отправьте заново одновременно обновлённый ZIP расширения и совпадающий исходный пакет; не прикладывайте новые исходники к старому бинарному ZIP.

## 4. Проверка полного совпадения

После запуска сборки сравните SHA-256 файла `release/MajesticToolkit-1.5.5-firefox.zip` с хешем **фактически отправляемого** ZIP. На Linux/macOS выполните `sha256sum release/MajesticToolkit-1.5.5-firefox.zip`; на Windows PowerShell — `Get-FileHash release/MajesticToolkit-1.5.5-firefox.zip -Algorithm SHA256`. `release/SHA256SUMS` генерируется автоматически вместе с релизными архивами. Если файл расширения и исходный архив пересобирались отдельно, сравните контрольные суммы. Не прикладывайте исходники версии 1.5.5 к ранее отправленному ZIP версии 1.0.0.
