# MajesticToolkit 2.3.7 — Совместная работа с тактическими материалами
> **Архив релиза.** Здесь сохранены возможности, проверки и ограничения, актуальные на момент выпуска 2.3.7. Полная последовательность изменений — в [истории версий](../CHANGELOG.md).


## Функционал (реализован в коде)

Общие командные тактические записи работают на существующем Cloud Identity Server (Node.js 22 / SQLite):

- **Карты:** метаданные, проверяемые изображения PNG/JPEG/WebP (до 25 МиБ на изображение, до 5 непубликованных и опубликованных подложек на профиль), разметка, слои, калибровка и привязки территорий. Изображения передаются через фоновый процесс браузера; access-токен не передаётся в HTML-интерфейс.
- **Планы:** исходные журналы операций, отряды, точки, маршруты и архивирование.
- **Аирдропы:** точки, события, участники, получение наград, завершение и отмена.
- **Территории:** записи Crime & Territory, территориальные события и история владения/каптов.
- **Совместная работа:** версии каждой серверной записи, история действий и авторов, запрет перезаписи при конфликте (`409`), идемпотентные ключи операций, транзакционное сохранение, защита связанных объектов, история редакций в `cloud_tactical_changes`.
- **RBAC:** `Viewer` — просмотр; `Editor`, `Admin`, `Owner` — публикация, изменение и разрешённое удаление. Проверка роли и сессии проводится перед записью внутри транзакции. Команды и облачные RP-профили строго изолированы.
- **Клиент:** отдельный раздел «Collaborative Tactical Workspace» в Team & Cloud, выбор локального источника, публикация, серверное редактирование, журнал изменений, постраничный просмотр и явное получение на устройство.

### Начало работы

1. Обновите полный проект **2.3.6** изменёнными файлами из архива 2.3.7.
2. Запустите `npm run cloud:identity`. Существующая SQLite-база автоматически получает новые таблицы. Не удаляйте существующую базу.
3. В расширении войдите в облачный аккаунт, выберите команду и привяжите локальный RP-профиль к облачному профилю **того же проекта и игрового сервера**.
4. Откройте раздел Collaborative Tactical Workspace. Сначала опубликуйте территорию, затем карту (если она ссылается на эту территорию), затем точки аирдропов, события и планы. Карта должна быть опубликована до записей, требующих её SHA-256.
5. Другие участники той же команды увидят записи после обновления Team & Cloud и смогут редактировать их, если их роль позволяет. Изменения не затирают локальные журналы автоматически. Для получения отдельной записи нажмите «Получить в локальный RP-профиль».

Для карт разных редакций предусмотрена отдельная операция **явной замены локальной карты**. Если локальная запись отличается от облачной, обычный импорт остановится без перезаписи. При замене карты серверная копия не изменяется. При отличающейся подложке локальная защита зависимых планов и аирдропов может заблокировать замену.

### Безопасность и ограничения

- Пользователь **явно** выбирает, что публиковать; частные карты, планы и журналы никогда не передаются автоматически. Включение старой Multi-Device Sync для семей, организаций и товаров **не включает** автоматическую тактическую синхронизацию.
- Это совместное **серверное** рабочее пространство с ручной публикацией и получением. Фоновая офлайн-очередь версии 2.3.4 **не распространяется** на тактические материалы; для них необходима доступность Cloud Identity Server. Реалтайм-совместное редактирование в одном текстовом/графическом редакторе (CRDT) не заявляется. Используется optimistic concurrency и ручное обновление списка.
- Бинарные изображения пока хранятся в SQLite в составе командного сервера. Выделенное облачное файловое хранилище относится к 2.3.8. Организуйте регулярный backup SQLite, включая WAL/SHM, и TLS на публичном сервере. Сервер без сертификата допускает только локальные адреса.
- Объём JSON одной записи ограничен 256 КиБ, входящий запрос ограничен 512 КиБ, на RP-профиль до 2000 активных тактических записей. Проверяются сигнатуры и геометрические размеры изображений; это не заменяет полного декодирования изображения на принимающем устройстве.
- Чужие локальные RP-профили, данные других команд и прямые HTTP-запросы без полномочий не должны давать доступ. Вход и Team RBAC остаются серверными.
- Tactical Analytics, офлайн-симуляции, Evidence Vault, локальные приватные ссылки и Backup v21 **не публикуются** в этом релизе и продолжают работать автономно. Ссылка на карту хранится по SHA-256; существующие локальные модули не начинают читать облако без явного импорта.

### Проверки

- `node --test tests/cloud-tactical-237.test.mjs tests/cloud-tactical-client-237.test.mjs` — реальный HTTP/SQLite с несколькими пользователями и тест фонового клиента.
- `python3 tests/browser-cloud-tactical-237.py` — Chromium DOM-проверка Team Tactical UI (требуется Playwright и Chromium).
- `npm run verify` — полный набор Node-тестов, четыре браузерные сборки, проверка пакетов и SHA-256.

Локальные тесты не заменяют публичный HTTPS-пилот, ручную установку расширений на всех браузерах и нагрузочную приёмку.
