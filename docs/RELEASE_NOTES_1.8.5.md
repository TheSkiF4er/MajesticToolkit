# MajesticToolkit 1.8.5 — Case Dossier & Export

Production implementation extending MajesticToolkit 1.8.4 without replacing existing complaint, evidence, knowledge or moderation modules.

## Рабочий интерфейс

- **Workspace → Жалобы → Досье и экспорт ↗** в карточке конкретной жалобы.
- Досье составляется из текущей реальной записи жалобы, Evidence Timeline, связанных доказательств Evidence Vault, зафиксированных цитат/связей Knowledge Graph, структурированных решений Punishment Registry и локального аудита.
- Предпросмотр отчёта перед экспортом, выбор формата **JSON, HTML, TXT, BBCode или ZIP**. Есть явное исключение доказательств или пользовательских заметок, никнеймов и реестра; исключение не гарантирует абсолютной анонимизации URL/описаний.
- ZIP-досье содержит `dossier.json`, `report.txt`, `report.html`, `manifest.json` и `attachments/<ID>.bin` для доступных локальных файлов. Внешние ссылки не скачиваются. Отсутствующие файлы перечислены с явным статусом `missing`, неполный архив требует подтверждения. Для повреждённых файлов с неверным SHA-256 экспорт блокируется.
- Встроенная проверка ZIP-досье после импорта: точный состав ZIP, CRC-32, SHA-256 для каждого элемента и вложения, соответствие ID жалобы и профиля, отсутствие незаявленных файлов. Досье не применяет серверных действий.

## Резервное копирование и миграция

- **Backup v17 (JSON):** все прежние данные и метаданные Evidence Vault в `evidenceVault`; сам бинарный контент IndexedDB в JSON **не входит**. Импорт копий v1–v16 сохранён, в том числе существующих жалоб и исторических связей.
- **Переносимый ZIP v17:** `backup.json` + двоичные файлы Evidence Vault + `manifest.json` с SHA-256. Перед экспортом проверяются все вложения и ссылки из жалоб/реестра на наличие материалов. Отсутствующие файлы запрещают объявлять архив полным.
- При восстановлении ZIP сначала проверяется весь пакет, а в IndexedDB добавляются файлы с исходными ID, без перезаписи конфликтующих записей. Если восстановление остальных данных завершается ошибкой, новые файлы удаляются в рамках отката. Сохраняется действующая точка восстановления для `storage.local` (она сама по себе **не** содержит бинарные файлы).
- В ZIP поддерживается стандартный формат ZIP STORE без сжатия, ZIP64, исполняемых вложений и удалённой загрузки. Максимальный размер ZIP — 300 МиБ. Другие ZIP-упаковщики и произвольные ZIP-архивы не являются импортируемыми форматами.
- Для полного переноса используйте **именно ZIP v17**, не JSON. Весь перенос осуществляется вручную и локально.

## Ограничения

- Если файл отсутствует в IndexedDB, ZIP-досье можно сформировать только с явной пометкой и подтверждением. Переносимый общий ZIP с отсутствующим материалом, упомянутым жалобой или реестром, блокируется.
- Контрольные суммы определяют целостность локальных данных; они **не** доказывают достоверность или официальность доказательств и не являются цифровой подписью.
- Досье фиксирует локальные сведения пользователя; изменение, удаление и отправка материалов на форум остаются ручными. Выполнение игровых наказаний и серверные действия не автоматизируются.
- Объём IndexedDB зависит от браузера; больших объёмов может не хватить для формирования ZIP или импорта. Внешние HTTPS-ресурсы остаются ссылками.
- Chromium browser E2E используют автономную фикстуру с имитацией IndexedDB, без доступа к реальным авторизованным форумам. Firefox Android/Safari сборки проверяются статически, а не на физическом устройстве.

## Проверки

`npm run verify` — модульные и регрессионные тесты, синтаксис/манифесты 4 платформ, ZIP и SHA-256. `npm run test:browser` — Chromium E2E с созданием ZIP-досье, настоящим скачиванием, сравнением контрольных сумм и восстановлением бинарного файла с исходным ID из переносимого архива.
