# MajesticToolkit 2.0.7 — Редактор процессуальных документов
> **Архив релиза.** Здесь сохранены возможности, проверки и ограничения, актуальные на момент выпуска 2.0.7. Полная последовательность изменений — в [истории версий](../CHANGELOG.md).


**Дата:** 2026-11-18. **База:** загруженная пользователем версия 2.0.6. **Тип:** работающий функциональный релиз.

## Сквозной сценарий

1. В `#justice` → «Судебные дела» создать либо открыть дело с действующим судом и участниками. Раскрыть «Сформировать процессуальный документ», выбрать иск, заявление, ходатайство, повестку, определение, постановление, протокол, решение или апелляционную жалобу. Правовые основания и требования вводятся пользователем — система не утверждает правильность RP-законодательства.
2. После создания запись одновременно сохраняется в `majesticDocumentV7:` и прикрепляется к делу в `majesticGovernmentV6:` с новой записью истории дела. Редактор Document Studio автоматически открывает созданный черновик с заполненными реквизитами суда, номера, категории, территории, сторон и доступного судьи. Изменение исходного дела не меняет уже созданную редакцию.
3. Редактировать исходные значения переменных и текст шаблона; предварительный просмотр обновляется по мере ввода. Сохранить новую редакцию, при необходимости просмотреть прошлые, восстановить историю, экспортировать PDF, скопировать текст или вставить через действующий XenForo-инструмент.
4. Проверить на месте правовое основание, обстоятельства, резолюцию и подписанта. Нажать «Утвердить редакцию» и вручную указать подписанта, совпадающего с полем документа. Программа считает SHA-256 снимка этой конкретной версии и сохраняет запись утверждения. Проверка SHA-256 доступна из просмотра; при ошибке экспорта проверка останавливает работу.
5. Исправления не переписывают утверждённую редакцию: редактор создаёт новую версию-черновик. Исходный документ остаётся связанным с делом и не может быть удалён или перенесён в другую карточку. Создание копии делает независимый обычный документ без чужих подтверждений.

## Совместимость и границы

- Все прежние шаблоны/документы без `procedural` читаются в исходном формате. Новое необязательное поле в Document Studio хранит вид документа, ID и редакцию дела на момент создания, время генерации и утверждения редакций. Валидация резервных копий и импорт проверяют связи с профилем и делом и SHA-256 подписанных версий. Дополнительная таблица, сервер, API или разрешения браузера не требуются.
- Утверждение является **отметкой в локальном расширении**, а не квалифицированной электронной подписью, внешним судебным постановлением или подтверждением полномочий подписанта.
- PDF формируется существующим браузерным растровым генератором Document Studio для многостраничного вывода с кириллицей. **Выделение и поиск текста внутри PDF не поддерживаются в текущем генераторе.** Извлечение текста доступно через действие «Копировать текст».
- Тексты документов являются редактируемыми RP-черновиками. Проверку нормативных оснований, подсудности, доказательств и точности процессуальных формулировок пользователь проводит самостоятельно.

## Проверки

- `npm test` — регрессионный набор и новые тесты создания, атомарного связывания, утверждения версий, SHA-256, импорта/экспорта, профилей и отката повреждённой записи.
- `npm run test:browser:procedural` — Chromium E2E с открытием и реальным заполнением форм, регистрацией дела, созданием и утверждением документа.
- `npm run verify` — тесты, сборки расширения для Chromium/Firefox/Firefox Android/Safari, проверка синтаксиса и пакетов.

**Установка:** применить патч к полному дереву 2.0.6 и выполнить `npm run verify`.
