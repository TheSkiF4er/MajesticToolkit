# MajesticToolkit 1.9.4 — AI Technical Support

## Работающие функции

- **Workspace → AI / Поддержка → AI Technical Support** и **Настройки → Открыть диагностику и техподдержку**. Помощь доступна локально даже при отключённом AI. Отдельное согласие требуется перед каждым запросом в OpenAI.
- Локальные **проверки по кнопке**: версия расширения, доступность чтения `storage.local`, наличие API IndexedDB, оценка квоты хранилища, разрешения двух форумов и локального шлюза. Проверка соединения шлюза по отдельной галочке и при наличии токена. Проверки не меняют настройки и не запрашивают новые разрешения. Наличие IndexedDB API не означает, что каждый файл цел.
- Руководства по шести категориям: общая настройка, форумы, резервные копии, Evidence Vault, AI, интеграции. Локальные инструкции помогают без подключения и ключей. Отчёт JSON скачивается по отдельной кнопке; содержит лишь версию, выбранную категорию и идентификаторы/статусы проверок. **Не содержит** токены, пользовательские файлы, полный дамп настроек, IP, URL, логи, никнеймы или тексты жалоб.
- **Облачная AI-помощь** через существующий локальный OpenAI Gateway (`mode:'support'`): маскировка типичных секретов и частных адресов в тексте ошибки, явный JSON-предпросмотр, обязательное согласие. Сервер принимает только допустимые коды диагностических проверок, отклоняет лишние поля и не принимает файлы. Ответ OpenAI — строгая JSON-схема с возможной причиной, шагами, вопросами и указанием необходимости ручной проверки. Без исполнения команд или изменения данных.
- Результаты и токен шлюза хранятся только в памяти текущей страницы; при переключении профиля очищаются. Настройки включения AI остаются в существующем ключе `mtAiConnectionV191`; формат Backup v17 не изменён. Журнал AI, содержание диагностического скана и история диалогов не записываются в хранилище.
- Отчёт можно проверить и вручную приложить к GitHub Issue. Никакая автоматическая публикация в GitHub не производится.

## Как пользоваться

1. Откройте **AI / Поддержка**; выберите тип ошибки, опишите симптомы без паролей и приватных данных.
2. Нажмите **Проверить расширение локально**. При необходимости включите **Проверить соединение с шлюзом** и повторите проверку.
3. Прочитайте рекомендации, при необходимости скачайте диагностический JSON.
4. Для необязательной облачной поддержки включите AI и локальный gateway как в версии 1.9.1, затем **Подготовить AI-запрос**. Изучите показанный JSON и разрешите его отправку отдельно. Инструкции модели являются советом, а не выполненной диагностикой или ремонтом.

## Безопасность и приёмка

- Отсутствуют удалённые операции над системой, автоматическое исправление настроек, массовая публикация и передача вложений. OpenAI не видит реальный браузер и не читает локальные логи.
- Модель по умолчанию изменена с неподтверждённого имени `gpt-6-luna` на документированную `gpt-4.1-mini`; при необходимости задайте `OPENAI_MODEL` вручную.
- Gateway остаётся на `127.0.0.1:32187` и использует серверный `OPENAI_API_KEY`, вводимый в окружении Node.js. Токен шлюза вводится пользователем в расширении и не сохраняется.
- Модульные тесты проверяют схему, секреты, профили, диагностические статусы, настоящий HTTP-обмен с поддельным OpenAI upstream и отказ от недоверенных полей. Chromium E2E проверяет интерфейс, сохранение отчёта, предпросмотр, согласие и смену профиля. Реальный платный вызов OpenAI и авторизованные форумы без учётных данных не тестировались.
