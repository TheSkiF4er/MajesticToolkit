# MajesticToolkit

**MajesticToolkit 2.3.3** — браузерное расширение для RP-форумов с необязательной облачной идентификацией. Основные локальные функции не требуют сервера; AI использует отдельный локальный шлюз.

**Cloud Storage & Migration (2.3.3):** раздел Team & Cloud позволяет создавать серверные RP-профили команд, связывать их с локальными RP-профилями того же проекта и сервера, выбирать семьи и организации и переносить их в постоянное SQLite-хранилище. Облачные записи читаются участниками команды; создавать профили могут Owner/Admin, импортировать — Owner/Admin/Editor. Повторная передача не дублирует данные, конфликт существующего ID отклоняется без перезаписи, локальные записи не меняются. Это ручной выборочный перенос, **не автоматическая синхронизация**. [Инструкция и API](docs/RELEASE_NOTES_2.3.3.md).

**Team Management & RBAC (2.3.2):** после входа в `#cloud` можно создавать команды, принимать и отзывать одноразовые приглашения, назначать роли Owner/Admin/Editor/Viewer, исключать участников, передавать владение и выходить из команды. Всё выполняется через настоящий Cloud Identity Server и SQLite: права проверяются **сервером при каждой операции**, токены приглашений хранятся только в виде SHA-256, а доступ других аккаунтов к чужим командам запрещён. Есть история командных событий, транзакции и межустройственное сохранение после перезапуска. Локальные RP-данные пока **не синхронизируются**. [Установка и проверки](docs/RELEASE_NOTES_2.3.2.md).

**Cloud Identity & Authentication (2.3.1):** новый раздел `#cloud` позволяет подключить самостоятельно развернутый Cloud Identity Server, создать облачный аккаунт (логин и пароль), войти, выйти, посмотреть активные устройства, отозвать отдельные сессии и завершить все сессии. Сервер `cloud-identity/server.mjs` использует SQLite и Node.js 22, хранит хеши паролей (scrypt) и токенов (SHA-256), ограничивает попытки входа, выдаёт 15-минутные токены доступа и ротируемые 30-дневные refresh-токены. Для внешнего доступа обязателен HTTPS с реальным TLS-сертификатом и список разрешённых Origins; локальный режим работает без облака. **Синхронизации рабочих данных, команд/RBAC и email recovery в 2.3.1 нет.** [Развёртывание и ограничения](docs/RELEASE_NOTES_2.3.1.md).

**Tactical Toolkit GA (2.3.0):** устранены риски потери данных при смене подложки и восстановлении Backup v21. Деструктивные действия с картой теперь проверяют зависимости не только активных, но и архивных планов, симуляций и точек аирдропов; повторная загрузка идентичной карты сохраняет разметку. При утрате карты возможно загрузить исходный файл с тем же SHA-256. Для сознательной очистки истории доступны удаление архивных планов и точек, завершённых событий после удаления связанных симуляций и источников. Общая блокировка сериализует изменения Tactical Store в пределах вкладки и через Web Locks API между окнами; rollback ZIP восстанавливает все исходные карты, даже если состав профилей менялся. Исправлен порядок replay для нескольких каптов за одну дату. Проверка: `npm run verify` и браузерные сценарии из CI; ручная приёмка установленного расширения на реальном RP-форуме и Safari/Android остаётся отдельным этапом. [Релиз 2.3.0](docs/RELEASE_NOTES_2.3.0.md).

**Tactical Integrations & Data Migration (2.2.9):** в разделе `#tactical` → «Связи и источники» прикрепляйте действующие документы Document Studio и ссылки/файлы Evidence Vault к территориям, аирдропам, планам и симуляциям. Источники защищены от удаления, а связи проверяются при импорте. В разделе «Резервная копия» создавайте **Backup v21**: JSON включает карту и её разметку, точки/события аирдропов, планы, симуляции и связи, но *не включает бинарное изображение карты*. Для полного переноса на другой браузер/устройство используйте **переносимый ZIP v21** со всеми картами и вложениями Evidence Vault. Импорт сверяет SHA-256 и ссылки **до записи**, затем выполняет восстановление с откатом при сбоях. Старые Backup v1–v20 читаются без удаления отсутствующих в них тактических записей. `npm run test:browser:tactical-backup` проверяет экспорт ZIP, очистку и восстановление в Chromium. [Релиз 2.2.9](docs/RELEASE_NOTES_2.2.9.md).

**Tactical Analytics & Replay (2.2.8):** `#tactical` → «Аналитика и replay» показывает подтверждённые в локальных журналах события каптов и аирдропов на общей временной шкале. Фильтруйте диапазон дат и категории, исследуйте рейтинги и дневную активность, воспроизводите изменения владельцев на загруженной карте и сравнивайте с сохранёнными модельными маршрутами (только как модель, не игровая телеметрия). Поддерживаются профильные настройки, CSV/JSON отчёты, проверка исходных журналов, кликабельные шаги и автоматическое воспроизведение. `npm run test:browser:tactical-analytics` проверяет сквозной сценарий Chromium. Системный Backup v20 пока не содержит подложку и тактические записи. [Релиз 2.2.8](docs/RELEASE_NOTES_2.2.8.md).

**Territory & Capture Mapping (2.2.5):** откройте `#tactical` → «Карта», нарисуйте полигон инструментом «Зона», выберите его и свяжите с уже созданной территорией из `#economy` → «Территории и капты». Карта отобразит цвет и имя владельца, капты, их результаты и состояние контроля на выбранную дату. Ссылки используют ID существующего Crime Store и сохраняются в IndexedDB карты; связанные полигоны защищены от случайного удаления и импорта несовместимой разметки. Капты остаются в исходном реестре, серверной телеметрии нет. `npm run test:browser:territory-map` проверяет процесс в Chromium. Backup v20 не включает изображения, разметку и связи; полный перенос — задача Backup v21. [Релиз 2.2.5](docs/RELEASE_NOTES_2.2.5.md).

**Airdrop Operations (2.2.4):** в `#tactical` → «Аирдропы» работает журнал RP-аирдропов: точки появления задаются кликом по карте или нормализованными координатами, события планируются по локальному времени, показывают обратный отсчёт, регистрируют участников, получение награды, завершение и отмену. Каждое изменение записывается в историю; поиск, статусные фильтры и раздельный по профилям CSV/JSON импорт/экспорт работают с реальным хранилищем. Данные не включены в Backup v20 — до Backup v21 переносите JSON отдельно. [Релиз 2.2.4](docs/RELEASE_NOTES_2.2.4.md).

**Map Layers & Markers (2.2.3):** `#tactical` → «Карта»: создавайте отдельные слои с управлением видимостью и блокировкой, размещайте метки, рисуйте линии и полигоны на настоящем Canvas, редактируйте подписи, цвет и вершины. Поддерживаются выбор и перетаскивание объектов, изменение порядка слоёв, поиск, фокусировка, отмена изменений и перенос JSON-разметки между картами одинакового размера. Разметка сохраняется атомарно с метаданными подложки в IndexedDB, отдельно для RP-профилей; старые карты 2.2.2 открываются без миграции. JSON-экспорт разметки не включает изображение. [Релиз 2.2.3](docs/RELEASE_NOTES_2.2.3.md).

**Interactive World Map (2.2.2):** `#tactical` → «Карта»: загрузка локальной подложки PNG/JPEG/WebP в IndexedDB, Canvas-панорамирование и масштаб, офлайн-работа, сохранение вида, трёхточечная калибровка игровых координат, SHA-256 и изоляция по RP-профилям. Изображение предоставляется пользователем; в Backup v20 оно не входит. [Релиз 2.2.2](docs/RELEASE_NOTES_2.2.2.md).

**Tactical Workspace (2.2.1):** новый раздел `#tactical` использует существующие территории, капты, семьи и организации. Рабочий Dashboard, поиск, фильтры событий и просрочки, избранное, история, быстрые действия и переходы к реальным редакторам Economy & Crime. Настройки сохраняются по RP-профилям; формат Backup v20 не меняется. В самом релизе 2.2.1 карта и аирдропы ещё отсутствовали. [Релиз 2.2.1](docs/RELEASE_NOTES_2.2.1.md).

**Economy & Crime GA (2.2.0):** в `#economy` → «Обзор» нажмите «Проверить все RP-профили». Система проверяет реальные записи рынка, склада, семей, организаций, территориальных событий, финансовых касс, старых сделок и связей с Document Studio/Evidence Vault; показывает статус каждой подсистемы и конкретные ошибки. Для создания Backup v20 исторический журнал проверяется строго: повреждённая запись блокирует экспорт, а не теряется молча. Оптимизирован расчёт месячных бюджетов. Сохранена совместимость с Backup v20 версии 2.1.9 без миграций, действуют локальные ограничения и отдельные источники финансовых данных. Новые browser E2E проверяют отказ при повреждении и успешный экспорт после исправления. [Релиз 2.2.0](docs/RELEASE_NOTES_2.2.0.md).

**Economy Integrations & Data Migration (2.1.9):** откройте `#economy` → «Импорт и связи». Доступны CSV/JSON-экспорт товаров, истории цен и объявлений и подтверждаемый импорт с предпросмотром, защитой от дубликатов, проверкой продуктов и профиля. Импорт добавляет записи под блокировкой без перезаписи существующих данных, откатывает частичное сохранение. Товары, семьи, организации и территории можно связывать по ID с существующими документами Document Studio и материалами Evidence Vault, удаление связанных записей блокируется. Общий экспорт/восстановление теперь использует **Backup v20** и переносимый ZIP с SHA-256 вложений; старые копии v1–v19 поддерживаются. Нет автоматической загрузки рыночных цен с RP-сервера и автоматической синхронизации финансов/склада. [Релиз 2.1.9](docs/RELEASE_NOTES_2.1.9.md).

**Advanced Economy Analytics (2.1.8):** откройте `#economy` → «Аналитика». Отчёты по сохранённым счетам и кассам: поступления, расходы, чистый денежный поток, сравнение с предыдущим равным периодом, остатки и бюджеты; по складу: результат продаж, себестоимость, списания и товары; по рынку: медианы фактических сделок/наблюдений, лучший активный спрос/предложение, динамика дневных медиан; экспорт CSV с защитой от формул. Выберите даты, владельца кассы и товар. Аналитика разделяет финансовый журнал, старые сделки и складской учёт — суммирование этих источников недопустимо из-за возможного дублирования операций. Рыночные данные локальные, без автоматических котировок. [Релиз 2.1.8](docs/RELEASE_NOTES_2.1.8.md).

**Financial Management (2.1.7):** откройте `#economy` → «Финансы». Создайте личную кассу или счёт, привязанный к семье/организации по стабильному ID. Укажите начальный остаток, фиксируйте поступления и расходы, переводите деньги между локальными счетами одной RP-профиля, задавайте месячные лимиты по категориям и проверяйте превышение бюджета. Переводы не дублируют сумму денег, операции не могут создавать отрицательный остаток, отменяется только последнее финансовое движение с сохранением события в журнале. Доступны изменение названия счёта, закрытие пустого счёта, поиск, CSV и необязательное поле `financeLedger` в Backup v19. Старые сделки `deal/cash`, склад и другие реестры не изменяются автоматически. Данные локальные, не отражают игровые банковские операции на сервере. [Релиз 2.1.7](docs/RELEASE_NOTES_2.1.7.md).

**Crime & Territory Operations (2.1.6):** откройте `#economy` → «Территории и капты». Создавайте территории с исходным владельцем, фиксируйте капты, организационные противостояния и RP-события, добавляйте участников и их показатели K/D и урона. Из завершённых каптов автоматически рассчитывается текущий владелец территории, а система отклоняет противоречивую цепочку захватов. Работают история, поиск, CSV, архивирование, рейтинги семей/организаций и игроков. События используют стабильные ID реестров семей и организаций и хранятся локально; связь с игровым сервером отсутствует. При экспорте и импорте Backup v19 проверяются новые поля `territories` и `crimeEvents`; старые резервные копии сохраняют текущий локальный журнал. [Релиз 2.1.6](docs/RELEASE_NOTES_2.1.6.md).

**Organizations & Assets (2.1.5):** откройте `#economy` → «Организации». Доступны реестр организаций, подразделения и иерархия, должности и кадровые назначения, имущество с ответственными и инвентарными номерами, списание, журнал изменений, CSV и профильный поиск. Остатки складского журнала отображаются для совпадающего имени владельца-организации, но не дублируют стоимость ручного реестра. Данные входят в необязательное поле `organizations` Backup v19; старые копии без него не удаляют организации при сохранении текущих профилей. Все функции локальные, без серверной синхронизации и подтверждения игровых полномочий. [Релиз 2.1.5](docs/RELEASE_NOTES_2.1.5.md).

**Families & Membership (2.1.4):** откройте `#economy` → «Семьи и игроки» и создайте семью. В семейном реестре работают ранги с приоритетами, приём и выход участников, кадровые изменения, архивирование, поиск, история событий и CSV состава. Имена старых матчей можно вручную привязать как исторические псевдонимы без изменения записанных результатов; статистика семьи рассчитывается по настоящим матчам текущего профиля. Данные семей входят в Backup v19 как проверяемое необязательное поле `families`; старые копии без него не удаляют локальные семьи при восстановлении. Это локальные RP-записи, не серверная проверка статуса и не синхронизация состава. [Релиз 2.1.4](docs/RELEASE_NOTES_2.1.4.md).

**Trading & Inventory (2.1.3):** откройте `#economy` → «Склад и имущество». Закупайте партии товаров из Marketplace, продавайте часть остатка, передавайте между личным владельцем, семьёй и организацией, резервируйте и списывайте единицы. Для штучного имущества задавайте уникальный инвентарный номер. В журнале отражаются реальные операции, а реализованная прибыль учитывает закупочную себестоимость и комиссии. Доступны поиск, история отмен, CSV и полный Backup v19. Старые `deal`/`cash` не изменяются и **не пополняются автоматически** из склада. Нет внешних котировок или автоматической синхронизации с RP-сервером. [Релиз 2.1.3](docs/RELEASE_NOTES_2.1.3.md).

**Marketplace & Price Intelligence (2.1.2):** откройте `#economy` → «Рынок и сделки». Здесь работает локальный каталог товаров с категориями, вариантами, единицами и архивированием; фактические наблюдения цен (предложение продажи, предложение покупки, завершённая сделка) с датой и вручную указанным источником; объявления о покупке и продаже со статусами и сроками. История цен, график, медиана, диапазон, лучший спрос/предложение и CSV строятся только из сохранённых записей. Рыночные записи изолированы по RP-профилям, привязаны к существующим товарам и включены в расширенный Backup v19 (JSON и переносимый ZIP); старые Backup v19 без поля `marketplace` не стирают новый каталог при импорте. Старые сделки `deal`, финансовые записи и статистика не изменены. **Нет автоматического получения котировок**, биржевой цены или серверной синхронизации. [Релиз 2.1.2](docs/RELEASE_NOTES_2.1.2.md).

**Economy & Crime Workspace (2.1.1):** раздел `#economy` теперь содержит шесть рабочих вкладок — обзор, рынок и сделки, финансы, семьи и игроки, калькуляторы и журнал. Обзор показывает реальную прибыль, расходы, открытый капитал, график и игровые показатели выбранного профиля, позволяет найти и открыть сохранённую запись. Редакторы сделок, доходов/расходов и матчей работают через существующее `economy-store.mjs`, без копирования и миграции финансов. Сохраняются вкладка, тип и запрос журнала, история открытий для каждого профиля; удаление профиля очищает его настройки. Группы семей строятся по текстовым названиям из матчей — это ещё не полноценный реестр организаций (запланирован на 2.1.5). Без сетевой загрузки цен. Backup v19 и прежние маршруты сохранены. [Релиз 2.1.1](docs/RELEASE_NOTES_2.1.1.md).

**Government & Justice GA (2.1.0):** в `#justice` → «Обзор» действует единая очередь судебной работы: просроченные и сегодняшние сроки, ожидающие ходатайства, ближайшие заседания, завершённые дела без утверждённого решения и апелляции на рассмотрении. Каждая задача открывает существующую карточку дела, не создавая копии данных. Кнопка «Проверить данные» сверяет связи судов, дел и процессуальных документов, SHA-256 решений и утверждённых редакций, метаданные судебных доказательств и бинарные файлы Evidence Vault. Экспорт **Backup v19** проводит сквозную проверку до выдачи файла; импорт v19 и старых v1–v18 выполняет preflight до замены данных. Переносимый ZIP v19 включает бинарные вложения с проверяемыми SHA-256; JSON сохраняет лишь метаданные, поэтому на новом устройстве для восстановления файлов выбирайте ZIP. AI-подключение по-прежнему требует отдельного согласия. Не реализованы серверная синхронизация и криптографическая подпись судьи. См. [релиз 2.1.0](docs/RELEASE_NOTES_2.1.0.md).

Проверка SHA-256 выполняется до экспорта утверждённой редакции, повреждённые утверждённые версии отклоняются при импорте. Документы остаются в действующих Government Store/Document Studio и Backup v18. Утверждение — локальная отметка пользователя, **не серверная подпись**; PDF остаётся существующим растровым экспортом Document Studio. [Заметки релиза](docs/RELEASE_NOTES_2.0.7.md).

## Сборка для Mozilla Add-ons — пошагово

Исходный пакет включает читаемые, вручную написанные исходные файлы без минификации, транспиляции и объединения. **Не прикладывайте в поле «Исходный код» папки `dist/` и `release/`: они генерируются.**

1. **ОС:** Linux x86_64 (проверено), также Windows 10/11, macOS 13+ или Linux с Node.js 22.
2. **Установите Node.js 22.16.0 и npm 10.9.2:** [официальная страница загрузки](https://nodejs.org/dist/v22.16.0/) → выберите MSI/PKG/архив для вашей ОС → завершите установку → откройте новый терминал.
3. Проверьте: `node --version` (ожидается `v22.16.0`) и `npm --version` (ожидается `10.9.2`).
4. Распакуйте **полный исходный код** в пустой каталог; перейдите в этот каталог в терминале.
5. Выполните `npm run build-for-amo`. **`npm install` не нужен**, внешних npm-зависимостей нет.
6. Готовый Firefox ZIP: `release/MajesticToolkit-1.8.1-firefox.zip`. Для полного тестирования выполните `npm run verify`; SHA-256 пакетов — в `release/SHA256SUMS`.

Сборка выполняет копирование исходных JS, формирование платформенных манифестов, проверку синтаксиса и разрешений, воспроизводимую упаковку и контрольные суммы. Компиляция или генерация исходного JS не выполняется. Подробная инструкция, включая ручное развёртывание Node для каждой ОС: **[docs/AMO_BUILD.md](docs/AMO_BUILD.md)**.

**Контрольная сумма Firefox-архива 1.8.0:** сверяйте `release/MajesticToolkit-1.8.1-firefox.zip` с соответствующей строкой актуального `release/SHA256SUMS`, созданного тем же исходным коммитом. Для Mozilla AMO загружайте Firefox ZIP и исходный код из одной версии.

## Настройка XenForo 1.1.0 (сохранена в 1.5.5)

1. В разделе «Профили» создайте профиль для Majestic RP (`https://forum.majestic-rp.ru/`) или Russia Online (`https://forum.russia.online/`). Выберите его активным, если работаете с несколькими персонажами на одном форуме.
2. В разделе «Сайты и доступ» отдельно предоставьте разрешение нужному форуму, затем обновите вкладку.
3. В разделе «Форум» добавьте шаблон, выбрав профиль и формат BBCode или plain. На странице форума появится плавающая панель; горячие клавиши Alt+Shift+1…9 применяются к активному редактору.
4. В разделе «Форум → Пользовательская навигация» создайте ссылку HTTPS, выберите профиль или «Все профили». Она появится в доступной шапке XenForo и будет открываться в новой вкладке. Записи можно редактировать или удалять.
5. На публичной странице `/members/…` плавающая панель показывает только имя, статус и поля, уже отображаемые форумом. Закрытые сведения, информация о персонажах и жалобы не извлекаются.
6. На странице `/threads/…` можно открыть штатные инструменты модерации, только если интерфейс сайта показывает соответствующее действие и у пользователя есть права. MajesticToolkit не отправляет модераторские запросы самостоятельно.

Данные двух форумов разделяются по домену, активному профилю и ID сервера. Если текущий выбранный профиль относится к другому домену, выбирается первый профиль совпадающего форума. Для нескольких серверов на одном домене назначайте активный профиль вручную. Пользовательские ссылки входят в резервную копию формата v10; копии v1–v9 поддерживаются. Фоновый сбор профилей запрещён; поведение интерфейса форумов может отличаться из-за темы XenForo и установленных дополнений.

## Server Monitor (1.2.0)

1. Откройте **Серверы и игроки**, нажмите **Разрешить официальный API**. Запрашивается *только* `https://api.majestic-files.com/*`; другие сайт-разрешения не меняются.
2. Нажмите **Обновить каталог**. В актуальном публичном ответе `/meta/general` представлены серверы Majestic RP и Россия Онлайн; записи сохраняются локально. Отметьте нужные серверы звёздочкой.
3. **Проверить онлайн** выполняет отдельный запрос `/meta/servers`. Точные значения появляются **только если** ответ содержит проверяемые поля ID и числового количества игроков. Этот endpoint не удалось проверить из тестовой среды; он может оказаться недоступным, измениться или не предоставлять онлайновые показатели. В этих случаях показывается ошибка, а онлайн **не подменяется вымышленными цифрами**. Дата последнего успешного обновления показывается отдельно.
4. После первого успешного обновления онлайна можно включить **Автообновление**. Оно работает только пока открыто рабочее пространство и вкладка видима (не чаще одного раза за пять минут), не запрашивает новые разрешения и не выполняет скрытое сканирование.
5. На разрешённом XenForo-форуме откройте общедоступную страницу `/members/…`, затем панель MajesticToolkit → **Сохранить карточку**. Сохраняются только имя, статус и видимые на странице показатели, привязанные к правильному локальному профилю. Запросы к приватным профилям, служебным страницам и сторонним доменам исключены.
6. Копия **v11** переносит избранное, ранее полученные сведения и сохранённые карточки. Старые копии v1–v10 поддерживаются с сохранением существующих карточек при совместимых профилях.

**Источник данных:** [Majestic/Russia Online Masterlist](https://masterlist.majestic-rp.ru/) и [публичное API](https://api.majestic-files.com/meta/general). Сервер доступен без токена, но официально задокументированной гарантии стабильности и режима использования API нет; расширение обращается к нему исключительно по запросу пользователя или его явно разрешённому автообновлению. Нет собственной серверной базы, выдуманной статистики или автоматического доступа к закрытым данным.

Из готовых ZIP нельзя установить Safari как обычное приложение: это ресурсы WebExtension. Для macOS Safari доступны временная установка или упаковка в приложение через Xcode. Chromium на ПК требует загрузить **распакованную папку**, а не сам ZIP.

При наличии исходников и Node.js 22 можно подготовить проверенные каталоги командами `npm run prepare:chromium` / `npm run prepare:safari` (после `npm run verify`).

## Установка для разработки

- **Chrome, Edge, Brave и аналогичные Chromium:** распакуйте `release/MajesticToolkit-1.5.6-chromium.zip` и откройте `chrome://extensions` → режим разработчика → «Загрузить распакованное расширение».
- **Firefox Desktop:** используйте `about:debugging#/runtime/this-firefox` → «Загрузить временное дополнение» → выберите `manifest.json` из распакованного `release/MajesticToolkit-1.8.1-firefox.zip`. Для постоянной установки необходимо подписать пакет через Mozilla AMO.
- **Firefox Android:** используется отдельный архив с адаптированным интерфейсом и без десктопной панели; доступность установки неподписанных дополнений зависит от версии и режима Firefox Android.
- **Safari:** `release/MajesticToolkit-1.5.6-safari.zip` содержит ресурсы WebExtension; на macOS Safari поддерживает временную установку через Developer → Add Temporary Extension, а для постоянной установки/распространения требуется упаковка в приложение (Xcode/App Store Connect). Это **не IPA/APP**.

После обновления сохраняйте **тот же идентификатор расширения** и профиль браузера. Не удаляйте установленную версию без экспортированной резервной копии.

## Данные и восстановление

При импорте резервной копии создаётся точка отката с SHA-256 в `storage.local` (макс. 20 МиБ). Она сохраняется при перезапуске браузера и позволяет вернуть прежние данные, включая записи форума/экономики/законов/документов. Импорт поддерживает предыдущие форматы v1–v9, основной ключ состояния не переименовывался. Восстановление доступно на вкладке «Резервные копии» и при ошибке загрузки состояния. Снимок не включает OAuth-токены и не изменяет посторонние ключи хранения. Для копий свыше 20 МиБ **сначала экспортируйте JSON в файл**. Снимок не заменяет внешние бэкапы.

## Подача в Mozilla AMO

Сборка Firefox содержит декларацию данных: обязательная передача отсутствует, необязательные категории используются при пользовательском подключении Google. Официальный сайт дополнений требует указать категории передачи данных при загрузке. См. [инструкцию AMO](docs/AMO_SUBMISSION.md) и [политику приватности](docs/PRIVACY.md). Стабильный Gecko ID: `majestictoolkit@theskif4er.github.io`; не менять после первой публикации.

## Безопасность и интеграции

Разрешения на RP-форумы и видеосайты запрашиваются отдельно. Контентные скрипты читают данные через ограниченный интерфейс фонового процесса; в Chromium доступ к `storage.local` из недоверенных контекстов дополнительно отключён. Публикация сообщений/наказаний не должна происходить без действий пользователя. Подключение Google требует собственного OAuth-клиента, зарегистрированных Redirect URI и ограниченного доступа к файлам. Автоматическая синхронизация с Docossum не выполняется без согласования с владельцем.

### Tactical Planning (2.2.6)

В разделе **Tactical Toolkit → Планирование** используйте ранее загруженную карту: создайте план, выберите семью/организацию, добавьте группы, командиров и участников, отметьте точки на Canvas, составьте маршрут из точек. Поддерживаются альтернативные планы, история изменений, архивирование и экспорт JSON/текстового отчёта. Время маршрута — оценка в пикселях по вручную заданной скорости, не игровая телеметрия. Для экспорта сохранённых данных до внедрения Backup v21 используйте кнопку «Экспорт всех планов JSON».


### Tactical Simulation Engine (2.2.7)

Во вкладке **Tactical Toolkit → Симуляции** выберите сохранённый план с маршрутами и задайте время старта, условную скорость, остановки, допустимый радиус пересечения, seed и число прогонов. Кнопка «Запустить и сохранить» рассчитывает временную шкалу, условные пересечения маршрутов и сводку повторных прогонов. На Canvas доступны просмотр всех маршрутов и перемещение расчётных позиций по ползунку времени. Выберите другую сохранённую симуляцию для сравнения длительности, дистанции и числа пересечений; доступен JSON-экспорт снимка и CSV таймлайна.

Моделирование использует **пиксели карты и введённые вручную параметры**, не считывает координаты из игры и не предсказывает шансы на победу. Результаты хранятся отдельно от фактических каптов и исходных планов. Для переноса до Backup v21 используйте «Экспорт JSON»; Backup v20 не содержит симуляции, планы и бинарные подложки.
