## Всё необходимое для RP-работы

MajesticToolkit объединяет инструменты, которые обычно приходится вести в разных вкладках, таблицах и файлах. Основные разделы работают локально и не требуют облачного аккаунта. Внешние подключения — включая Google, ИИ и собственный сервер команды — включаются отдельно.

| Направление | Возможности |
| :--- | :--- |
| **Форум** | Шаблоны и вставка BBCode, пользовательская навигация XenForo, доступные действия модерации, оформление интерфейса. |
| **Жалобы и модерация** | Учёт обращений, этапы проверки, сроки, черновики решений, реестр наказаний, история действий. |
| **Доказательства и знания** | Материалы дел, временные шкалы, досье, связи между источниками и поиск по сохранённым записям. |
| **Законы и государственные инструменты** | База нормативных материалов, редакции, дела, судебные процедуры и подготовка документов. |
| **Экономика и организации** | Товары и сделки, инвентарь, финансы, семьи, организации, имущество и территории. |
| **Тактическое планирование** | Собственные карты, слои и метки, аирдропы, маршруты, симуляции и воспроизведение локальных событий. |
| **Команда и облако** | Аккаунты и роли, приглашения, синхронизация выбранных RP-данных, общие справочники, знания и файлы. |
| **Дополнения** | Необязательный локальный шлюз ИИ, подключение Google Workspace, экспорт и резервные копии. |

> **Принцип работы.** MajesticToolkit не выдаёт моделирование за игровую телеметрию, не обходит права форумов и не публикует решения автоматически. Точность пользовательских материалов, санкций и импортированных справочников необходимо проверять по первоисточнику.

## Что нового в версии 2.4.0

Выпуск **«Командная работа и облако»** сосредоточен на безопасности общих материалов и надёжности восстановления данных.

- **Приватность версий файлов.** Исторические редакции, отмеченные как личные, доступны только владельцу — даже если следующая версия опубликована для команды.
- **Проверяемые резервные копии.** При создании, проверке и восстановлении серверной копии контролируются содержимое, размеры и SHA-256 файлов, их версий и изображений карт.
- **Сквозные проверки команды.** Реальный HTTP/SQLite-сценарий охватывает аккаунты, права, синхронизацию, знания, вложения, аудит и восстановление.
- **Четыре браузерных пакета.** Сборка и контроль целостности для Chromium, Firefox, Firefox Android и ресурсов Safari.

## Быстрый старт

### 1. Установите расширение

1. Перейдите на [страницу выпуска 2.4.0](https://github.com/TheSkiF4er/MajesticToolkit/releases/tag/v2.4.0) и скачайте пакет для браузера вместе с `SHA256SUMS`.
2. Сверьте контрольную сумму файла. Для Chromium распакуйте архив и выберите папку с `manifest.json` в меню расширений → **Режим разработчика** → **Загрузить распакованное расширение**.
3. Откройте MajesticToolkit, создайте RP-профиль и выберите нужный сервер.
4. В разделе **«Сайты и доступ»** предоставьте доступ только форумам, которыми собираетесь пользоваться. Обновите открытую вкладку форума.

[Подробная установка Chromium и Safari](docs/INSTALL_CHROMIUM_SAFARI.md) · [Подготовка пакета Firefox](docs/AMO_BUILD.md)

### 2. Начните работать локально

Создайте профиль, добавьте шаблоны форума, жалобу или документ. Локальные данные хранятся в браузере; облачный сервер, Google и ИИ для этих базовых операций не нужны. При работе с несколькими RP-профилями проверяйте активный профиль перед переносом материалов.

### 3. При необходимости подключите команду

Раздел **«Команда и облако»** позволяет использовать самостоятельно развёрнутый сервер: входить в аккаунт, создавать команды, назначать роли, публиковать выбранные данные и управлять общими файлами. Синхронизация не включается автоматически. Перед её активацией ознакомьтесь с областью данных, доступных участникам команды.

[Командные возможности](docs/RELEASE_NOTES_2.4.0.md) · [Эксплуатация и резервное копирование](docs/RELEASE_NOTES_2.3.9.md) · [Безопасность](docs/SECURITY.md)

## Сборка из исходников

**Требования:** Node.js 22.x; внешние npm-зависимости для сборки проекта не требуются.

```bash
npm run verify
```

Команда запускает Node.js-тесты, собирает четыре варианта расширения, проверяет манифесты и полученные ZIP, формирует `release/SHA256SUMS` и `release/release-manifest.json`.

Для отдельных задач доступны:

```bash
npm run build-for-amo     # пакет для проверки и подачи в Mozilla
npm run test:cloud:ga     # сквозная проверка серверной командной работы
npm run cloud:load        # локальная краткая нагрузочная проверка
npm run ai:gateway       # необязательный локальный шлюз ИИ
npm run cloud:identity   # необязательный сервер команды
```

> **Важно:** сервер команды и шлюз ИИ не являются частью браузерного ZIP. Для публичного развёртывания сервера требуются HTTPS, контроль секретов, резервное копирование и отдельные приёмочные испытания. Локальная нагрузочная проверка не является гарантией производительности в production.

## Данные, доступ и конфиденциальность

- **Локально по умолчанию.** Рабочие записи остаются в хранилище расширения, если вы явно не включили внешнюю передачу или синхронизацию.
- **Разрешения по действию.** Доступ к RP-форумам, сайтам и необязательным интеграциям выдаётся пользователем отдельно.
- **Облачный режим под вашим контролем.** Для Team & Cloud нужен самостоятельно размещённый сервер; права проверяются сервером. Содержимое облачной базы не защищено сквозным шифрованием от администратора этого сервера.
- **ИИ только по согласию.** Для OpenAI нужен собственный ключ в локальном шлюзе; передаваемые данные показываются до отправки, а ответы требуют проверки человеком.
- **Резервные копии.** Перед переустановкой и миграцией экспортируйте данные. Не удаляйте старое расширение без резервной копии и не меняйте его идентификатор без проверки переноса.
