# MajesticToolkit

**MajesticToolkit 1.4.0** — самостоятельное расширение браузера для RP-форумов. Не требует собственной веб-платформы или сервера.

**Новый раздел 1.4.0:** [External Knowledge & Workspace](docs/KNOWLEDGE.md) — единая библиотека законов, документов, шаблонов и внешних ссылок, поиск, двусторонние связи, профильные Google Docs/Sheets-шаблоны и копирование доступного Google-файла с явного действия пользователя.

## Возможности

- **XenForo Integration (1.1.0):** единый адаптер для Majestic RP и Russia Online. Биндер BBCode, поиск редактора Froala/textarea, поддержка курсора и сочетаний клавиш; пользовательские ссылки непосредственно в навигации форума, общедоступные сведения с открытой страницы /members/, открытие только штатных инструментов закрытия/открытия и переноса тем (без автоматического выполнения и обхода прав).
- **Server Monitor & Player Profiles (1.2.0):** прямое чтение каталога Majestic RP и Russia Online из публичного API `api.majestic-files.com/meta/general` после отдельного разрешения. Избранные серверы, ручное обновление каталога/онлайна, необязательное автообновление подтверждённого онлайна раз в пять минут при открытом рабочем пространстве. Публичные карточки XenForo сохраняются кнопкой на текущей странице пользователя, без скрытых запросов. Поддерживаются резервные копии v12 (связи Центра знаний), а также импорт предыдущих форматов.
- Complaint Manager 1.4: локальные жалобы, ручной процесс рассмотрения, чек-листы, журнал действий, проекты решений, предупреждения за сутки/час/15 минут и по истечении срока; Evidence Studio: ссылки и таймкоды YouTube/Rutube/Twitch.
- Economy & Analytics: калькуляторы, сделки, финансовые операции, результаты игроков и семей, графики и CSV.
- Law Codex: импортируемые законы для каждого RP-сервера, редакции, поиск, сравнение, избранное и памятки.
- Government Tools: профили ведомств, решения, санкции, процессуальные шаблоны и фиксация применённых редакций законов.
- Document Studio: редактор и формы, локальные версии, экспорт многостраничного PDF. PDF формируется из изображений страниц, текст в нём не выделяется.
- External Knowledge & Workspace: справочники Fletcher Wiki для Majestic и Russia Online, Docossum-закладки, локальные связи между законами, документами, шаблонами и Google Docs/Sheets.
- External Integrations: OAuth PKCE для Google Docs, Google Sheets и Drive при наличии собственного Google OAuth Client ID; закладки на Fletcher Wiki и Docossum без скрытого извлечения данных.
- Productivity & UX: поиск по локальным разделам, ответы на основе локальных данных, темы, горячие клавиши, резервные копии.

**Важно:** в составе выпуска нет предзагруженной полной базы законов/предметов и нет онлайн-статистики всех игроков. Данные Law Codex добавляются пользователем. Нет собственного облачного ИИ и автоматического чтения Docossum/Fletcher Wiki.

## Сборка для Mozilla Add-ons — пошагово

Исходный пакет включает читаемые, вручную написанные исходные файлы без минификации, транспиляции и объединения. **Не прикладывайте в поле «Исходный код» папки `dist/` и `release/`: они генерируются.**

1. **ОС:** Linux x86_64 (проверено), также Windows 10/11, macOS 13+ или Linux с Node.js 22.
2. **Установите Node.js 22.16.0 и npm 10.9.2:** [официальная страница загрузки](https://nodejs.org/dist/v22.16.0/) → выберите MSI/PKG/архив для вашей ОС → завершите установку → откройте новый терминал.
3. Проверьте: `node --version` (ожидается `v22.16.0`) и `npm --version` (ожидается `10.9.2`).
4. Распакуйте **полный исходный код** в пустой каталог; перейдите в этот каталог в терминале.
5. Выполните `npm run build-for-amo`. **`npm install` не нужен**, внешних npm-зависимостей нет.
6. Готовый Firefox ZIP: `release/MajesticToolkit-1.4.0-firefox.zip`. Для полного тестирования выполните `npm run verify`; SHA-256 пакетов — в `release/SHA256SUMS`.

Сборка выполняет копирование исходных JS, формирование платформенных манифестов, проверку синтаксиса и разрешений, воспроизводимую упаковку и контрольные суммы. Компиляция или генерация исходного JS не выполняется. Подробная инструкция, включая ручное развёртывание Node для каждой ОС: **[docs/AMO_BUILD.md](docs/AMO_BUILD.md)**.

**Проверяемый SHA-256 нового Firefox-архива:** `d90ef7bfa058b415dc87357423585a33b0fbb5a35953eb4abca1dba29202143c`. Загрузите в Mozilla новый Firefox-пакет **вместе** с соответствующими исходниками (старый пакет после этих правок не совпадает с ними).

## Настройка XenForo 1.1.0 (сохранена в 1.4.0)

1. В разделе «Профили» создайте профиль для Majestic RP (`https://forum.majestic-rp.ru/`) или Russia Online (`https://forum.russia.online/`). Выберите его активным, если работаете с несколькими персонажами на одном форуме.
2. В разделе «Сайты и доступ» отдельно предоставьте разрешение нужному форуму, затем обновите вкладку.
3. В разделе «Форум» добавьте шаблон, выбрав профиль и формат BBCode или plain. На странице форума появится плавающая панель; горячие клавиши Alt+Shift+1…9 применяются к активному редактору.
4. В разделе «Форум → Пользовательская навигация» создайте ссылку HTTPS, выберите профиль или «Все профили». Она появится в доступной шапке XenForo и будет открываться в новой вкладке. Записи можно редактировать или удалять.
5. На публичной странице `/members/…` плавающая панель показывает только имя, статус и поля, уже отображаемые форумом. Закрытые сведения, информация о персонажах и жалобы не извлекаются.
6. На странице `/threads/…` можно открыть штатные инструменты модерации, только если интерфейс сайта показывает соответствующее действие и у пользователя есть права. MajesticToolkit не отправляет модераторские запросы самостоятельно.

Данные двух форумов разделяются по домену, активному профилю и ID сервера. Если текущий выбранный профиль относится к другому домену, выбирается первый профиль совпадающего форума. Для нескольких серверов на одном домене назначайте активный профиль вручную. Пользовательские ссылки входят в резервную копию формата v10; копии v1–v9 поддерживаются. Фоновый сбор профилей запрещён; поведение интерфейса форумов может отличаться из-за темы XenForo и установленных дополнений.

## Server Monitor (1.2.0)

1. Откройте **Серверы и игроки**, нажмите **Разрешить официальный API**. Запрашивается *только* `https://api.majestic-files.com/*`; другие сайт-разрешения не меняются.
2. Нажмите **Обновить каталог**. В актуальном публичном ответе `/meta/general` представлены серверы Majestic RP и Россия Онлайн; записи сохраняются локально. Отметьте нужные серверы звёздочкой.
3. **Проверить онлайн** выполняет отдельный запрос `/meta/servers`. Точные значения появляются **только если** ответ содержит проверяемые поля ID и числового количества игроков. Этот endpoint не удалось проверить из тестовой среды; он может оказаться недоступным, измениться или не предоставлять онлайновые показатели. В этих случаях показывается ошибка, а онлайн **не подменяется вымышленными цифрами**. Дата последнего успешного обновления показывается отдельно.
4. После первого успешного обновления онлайна можно включить **Автообновление**. Оно работает только пока открыто рабочее пространство и вкладка видима (не чаще одного раза за пять минут), не запрашивает новые разрешения и не выполняет скрытое сканирование.
5. На разрешённом XenForo-форуме откройте общедоступную страницу `/members/…`, затем панель MajesticToolkit → **Сохранить карточку**. Сохраняются только имя, статус и видимые на странице показатели, привязанные к правильному локальному профилю. Запросы к приватным профилям, служебным страницам и сторонним доменам исключены.
6. Копия **v11** переносит избранное, ранее полученные сведения и сохранённые карточки. Старые копии v1–v10 поддерживаются с сохранением существующих карточек при совместимых профилях.

**Источник данных:** [Majestic/Russia Online Masterlist](https://masterlist.majestic-rp.ru/) и [публичное API](https://api.majestic-files.com/meta/general). Сервер доступен без токена, но официально задокументированной гарантии стабильности и режима использования API нет; расширение обращается к нему исключительно по запросу пользователя или его явно разрешённому автообновлению. Нет собственной серверной базы, выдуманной статистики или автоматического доступа к закрытым данным.

## Требования и проверка

Node.js **22 LTS** для сборки; установка npm-зависимостей не нужна.

```sh
npm run verify
```

Команда запускает тесты, воспроизводимую сборку, проверку Manifest V3/разрешений/синтаксиса, создаёт ZIP-пакеты и проверяет SHA-256, каждый файл в ZIP и соответствие содержимому `dist/`.

## Установка для разработки

- **Chrome, Edge, Brave и аналогичные Chromium:** распакуйте `release/MajesticToolkit-1.4.0-chromium.zip` и откройте `chrome://extensions` → режим разработчика → «Загрузить распакованное расширение».
- **Firefox Desktop:** используйте `about:debugging#/runtime/this-firefox` → «Загрузить временное дополнение» → выберите `manifest.json` из распакованного `release/MajesticToolkit-1.4.0-firefox.zip`. Для постоянной установки необходимо подписать пакет через Mozilla AMO.
- **Firefox Android:** используется отдельный архив с адаптированным интерфейсом и без десктопной панели; доступность установки неподписанных дополнений зависит от версии и режима Firefox Android.
- **Safari:** `release/MajesticToolkit-1.4.0-safari.zip` содержит только ресурсы расширения; нужен контейнер Safari Web Extension, средства Apple и подпись. Это **не IPA/APP**, готового установочного приложения Safari в релизе нет.

После обновления сохраняйте **тот же идентификатор расширения** и профиль браузера. Не удаляйте установленную версию без экспортированной резервной копии.

## Данные и восстановление

При импорте резервной копии создаётся точка отката с SHA-256 в `storage.local` (макс. 20 МиБ). Она сохраняется при перезапуске браузера и позволяет вернуть прежние данные, включая записи форума/экономики/законов/документов. Импорт поддерживает предыдущие форматы v1–v9, основной ключ состояния не переименовывался. Восстановление доступно на вкладке «Резервные копии» и при ошибке загрузки состояния. Снимок не включает OAuth-токены и не изменяет посторонние ключи хранения. Для копий свыше 20 МиБ **сначала экспортируйте JSON в файл**. Снимок не заменяет внешние бэкапы.

## Подача в Mozilla AMO

Сборка Firefox содержит декларацию данных: обязательная передача отсутствует, необязательные категории используются при пользовательском подключении Google. Официальный сайт дополнений требует указать категории передачи данных при загрузке. См. [инструкцию AMO](docs/AMO_SUBMISSION.md) и [политику приватности](docs/PRIVACY.md). Стабильный Gecko ID: `majestictoolkit@theskif4er.github.io`; не менять после первой публикации.

## Безопасность и интеграции

Разрешения на RP-форумы и видеосайты запрашиваются отдельно. Контентные скрипты читают данные через ограниченный интерфейс фонового процесса; в Chromium доступ к `storage.local` из недоверенных контекстов дополнительно отключён. Публикация сообщений/наказаний не должна происходить без действий пользователя. Подключение Google требует собственного OAuth-клиента, зарегистрированных Redirect URI и ограниченного доступа к файлам. Автоматическая синхронизация с Docossum не выполняется без согласования с владельцем.
